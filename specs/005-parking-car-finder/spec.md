## Clarifications

### Session 2026-07-10

- Q: 진입 시 첫 화면과 화면 구조는? → A: **허브 구조** — 진입 시 활성 기록 없으면 등록 카메라(권한 거부 시 수동 폼), 있으면 요약 카드(허브). 요약 카드는 코드(최대 강조)·층·경과 시간·사진(탭 확대)과 [안내 시작]/[찾았어요]/[새 위치 등록] 액션으로 구성되며 폴백 화면을 겸한다. 등록 완료 화면은 별도로 두지 않고 요약 카드가 저장 확인을 겸한다. 되찾기 AR은 단일 화면 내 오버레이 상태 전환(관측부족→축/격자 안내→강등→도착)이며, 완료 처리 시 모듈을 닫고 홈으로 복귀한다.
- Q: 등록 방식과 인접 코드 수집 범위는? → A: **스캔 등록으로 재설계** — 진입 시 카메라 스캔이 시작되고 주변을 훑으면 기둥 코드들을 연속 자동 인식. 최근접 코드를 목표로 자동 선정(저장 직후 비차단 수정 가능), 신뢰도 있는 코드 1개 이상 확보 시 자동 저장, 코드 인식 프레임을 사진으로 자동 저장(수동 촬영·타이핑 불필요). 함께 인식된 코드들은 인접 관계로 상시 저장(스캔 부산물, MVP)하고 되찾기 중 목격되면 근접·도착 보조 신호로 활용(MVP). 저장된 배치를 현재 관측에 정렬하는 본격 매칭 알고리즘은 Later 유지. 수동 입력은 폴백(권한 거부·인식 실패)으로 격하.
- Q: 디버그 시각화의 활성화 방식은? → A: **기본 비활성 + 명시적 토글, 출시 빌드 포함** — 디버그 오버레이는 항상 표시가 아니라 기본 꺼짐 상태이며, 개발자 메뉴 또는 히든 제스처(특정 입력)로 켜고 끈다. 켜면 프로덕션 UI 위에 오버레이 레이어로 표시되어 내 차 찾기 동작이 올바르게 처리되는지(인식→채택/기각→앵커→격자→방향) 시각적으로 확인할 수 있다. 출시 빌드에도 포함해 실사용 환경(현장·TestFlight·일반 사용자 기기)에서 그대로 진단할 수 있게 하되, 일반 사용자가 우연히 발견하기 어려운 진입 방식으로 숨긴다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 스캔 등록과 기억 확인 (Priority: P1)

운전자가 지하주차장에 주차한 직후 앱의 내 차 찾기에 진입하면 카메라 스캔이 바로 시작된다. 차 옆에 서서 주변을 몇 초간 훑으면 앱이 주변 기둥 코드들을 자동으로 인식해 가장 가까운 코드를 내 차 위치로 저장하고("저장되었습니다 — B2-A-3"), 코드가 인식된 장면이 사진으로 함께 남는다. 타이핑도 별도 촬영도 없다. 볼일을 마치고 돌아왔을 때 앱을 열면 저장해 둔 코드·층·사진·주차 시각을 바로 확인해 차를 찾는 데 활용한다.

**Why this priority**: 등록이 "몇 초 둘러보기"로 끝나는 것이 이 기능의 핵심 마찰 제거이자 첫인상이다. 모든 후속 스토리의 기반 데이터(주차 기록 + 인접 코드 관계)가 여기서 만들어지고, 등록 시점에 해당 주차장에서 인식이 실제로 되는지 검증되는 효과(안 되면 즉시 수동 폴백 안내)도 있다.

**Independent Test**: 내 차 찾기 진입 → 주변 훑기 → 자동 저장 확인 → 요약 화면에서 목표 코드·사진 확인 → 앱 완전 종료 후 재실행 → 저장 정보가 그대로 표시되는지 확인.

**Acceptance Scenarios**:

1. **Given** 활성 주차 기록이 없고 카메라 권한이 허용된 상태, **When** 진입 후 주변을 훑어 기둥 코드가 1개 이상 신뢰도 있게 인식되면, **Then** 최근접 코드가 목표로 자동 저장되고 요약 화면에 "저장되었습니다"가 표시된다.
2. **Given** 스캔 중 코드가 여러 개(예: A-3, A-4, B-3) 인식된 상태, **When** 자동 저장되면, **Then** 최근접 코드가 목표로 선정되고 나머지는 인접 코드 관계로 함께 저장된다.
3. **Given** 자동 선정된 목표가 실제 내 차 기둥이 아닌 상태, **When** 요약 화면에서 함께 인식된 다른 코드를 선택하면, **Then** 목표가 즉시 수정된다(재스캔 불필요).
4. **Given** 인식된 코드에 층 표기가 없는 상태(예: "A-3"), **When** 저장이 진행되면, **Then** 층을 별도로 확인 입력받아 함께 저장한다.
5. **Given** 주차 기록이 저장된 상태, **When** 앱을 종료했다가 다시 실행해 내 차 찾기에 진입하면, **Then** 저장된 코드·층·사진·경과 시간이 표시된다.
6. **Given** 이미 활성 주차 기록이 있는 상태, **When** 새 주차 위치를 등록하면, **Then** 기존 기록 대체를 안내한 뒤 새 기록으로 대체한다.

### User Story 2 - 카메라 방향 안내로 차 되찾기 (Priority: P2)

돌아온 운전자가 주차한 층에 도착해 카메라 화면을 켜고 주변 기둥들을 비춘다. 앱이 읽힌 기둥 코드들의 번호 배열로부터 방향을 단계적으로 추정한다 — 코드 2개가 한 축에서만 다르면 그 축 방향의 안내를, 3개 이상이면 격자 전체 안내를 제공하고, 관측이 부족하면 무엇을 더 비춰야 하는지 구체적으로 알려준다. 번호 배치가 불규칙한 주차장이면 추정 모순을 스스로 감지해 "근처 도착 — 주변 기둥에서 직접 확인하세요" 모드로 정직하게 전환한다. 저장한 코드가 붙은 기둥을 직접 비추면 "도착"으로 확정된다.

**Why this priority**: 이 기능의 차별화 핵심(킬러 경험)이지만, P1의 저장 데이터가 있어야 동작하며 P1만으로도 최소 가치는 성립한다.

**Independent Test**: 코드가 저장된 상태에서 되찾기 모드 진입 → 기둥 코드를 1개→2개→3개 순서로 비추며 안내 단계가 전환되는지, 불규칙 배치를 흉내 냈을 때 강등되는지, 목표 기둥을 비추면 도착 확정되는지 확인.

**Acceptance Scenarios**:

1. **Given** 주차 기록(B2-A-3)이 있고 되찾기 모드에 진입한 상태, **When** 주변 기둥 코드를 1개만 인식한 상태이면, **Then** 방향 표시 대신 "주변 기둥을 더 비춰주세요" 안내가 표시된다.
2. **Given** 같은 구역에서 번호만 다른 코드 2개(예: B2-A-5, B2-A-7)가 인식된 상태, **When** 목표(B2-A-3)가 같은 구역이면, **Then** 번호 축을 따라 목표 방향 안내가 표시된다.
3. **Given** 구역과 번호가 모두 다른 코드 2개(예: B2-A-5, B2-B-7)만 인식된 상태, **When** 방향을 산출할 수 없으면, **Then** 부족한 관측을 특정한 안내(예: "같은 구역의 다른 번호 기둥을 하나 더 비춰주세요")가 표시된다.
4. **Given** 서로 다른 위치의 코드 3개 이상이 인식된 상태, **When** 격자 추정이 완료되면, **Then** 목표 방향 화살표·대략적 거리감·추정 신뢰도가 함께 표시된다.
5. **Given** 방향 안내가 진행 중인 상태, **When** 새로 읽은 코드의 위치가 현재 추정과 크게 어긋나면(불규칙 번호 배치), **Then** 화살표를 숨기고 "번호 배치가 불규칙합니다. 주변 기둥에서 B2-A-3을 직접 확인하세요" 근접확인 모드로 전환된다.
6. **Given** 방향 안내가 진행 중인 상태, **When** 저장된 목표 코드가 연속적으로 안정 인식되면, **Then** "도착"이 확정 표시된다. 일시적 오인식 한 번으로는 확정되지 않는다.
7. **Given** 주차 기록이 B2층인 상태, **When** 인식된 기둥 코드의 층이 B1 등 다른 층이면, **Then** "B2로 이동하세요" 층 불일치 안내가 표시된다.
8. **Given** 어둡거나 공간 인식이 어려운 구역이라 코드는 읽혔지만 위치 파악이 실패하는 상태, **When** 실패가 반복되면, **Then** 해당 코드는 층 확인·도착 확정에는 활용되고, "기둥에 더 가까이 가주세요 / 손전등을 켜보세요" 안내가 표시된다.
9. **Given** 등록 스캔에서 인접 코드(예: A-4)가 함께 저장된 상태, **When** 되찾기 중 그 인접 코드가 인식되면, **Then** 차량 근접 신호로 활용되어 추정 신뢰도가 상승하고 도착 판단의 보조 근거가 된다.

### User Story 3 - 수동 등록 폴백 (Priority: P3)

카메라 권한을 거부했거나, 저조도·비정형 표기로 스캔이 코드를 인식하지 못하는 주차장에서, 운전자가 기둥 코드를 직접 입력하고(필요 시 층 선택·사진 첨부) 등록을 마친다.

**Why this priority**: 스캔이 불가능한 환경·기기 상태에서도 기능의 최소 가치(위치 기억)가 성립해야 한다. 주 경로(스캔)가 있으므로 우선순위는 뒤이지만, 출시 범위에는 포함되어야 하는 안전망이다.

**Independent Test**: 카메라 권한 거부 상태에서 진입 → 수동 입력 폼 표시 → 코드+층 입력, 사진 첨부 → 저장 → 요약 화면에서 확인.

**Acceptance Scenarios**:

1. **Given** 스캔이 일정 시간 코드를 확보하지 못하는 상태, **When** 대기 시간이 경과하면, **Then** 수동 입력으로 전환할 수 있는 안내가 표시된다.
2. **Given** 카메라 권한이 거부된 상태, **When** 내 차 찾기에 진입하면, **Then** 수동 입력 폼이 기본으로 표시되고 등록·열람이 완전히 동작한다.
3. **Given** 수동 입력 폼, **When** 코드를 입력하고(층 선택, 사진 첨부 선택) 저장하면, **Then** 스캔 등록과 동일하게 요약 화면으로 저장이 확인된다.

### Edge Cases

- 코드 1개만 보이는 위치: 방향 추정 불가 → "주변을 더 비춰주세요"(US2-AS1).
- 코드 2개가 구역·번호 모두 다름: 방향 분해 불가 → 부족한 축을 특정한 추가 관측 안내(US2-AS3).
- 한 구역의 코드만 계속 읽는 경우: 다른 구역 방향을 알 수 없음 → "다른 구역 기둥을 비춰주세요" 안내.
- 차량 번호판(예: 12가3456)·안내문 등 코드가 아닌 텍스트: 등록된 코드와 표기 형식이 다르므로 후보에서 배제되어 안내를 오염시키지 않는다.
- 코드는 읽혔지만 공간 위치 파악 실패: 층 확인·도착 확정에만 활용 + 근접/손전등 안내(US2-AS8).
- 스캔 등록 중 위치 파악 실패(코드는 읽힘): 저장은 가능 — 위치 있는 코드가 있으면 그중 최근접, 전부 없으면 최다 관측 코드를 목표로 선정. 위치 없는 쌍의 인접 거리 정보는 생략(FR-002a).
- 주차장 코드 체계가 해석 불가(비정형 표기): 등록·열람은 정상 동작, 되찾기는 목표 직접 인식 전용 근접확인 모드(FR-016) + 사진 폴백으로 안내.
- 코드 오인식(가↔카, 0↔O, B↔8 등): 반복 인식으로 확신도를 올리고, 도착 확정은 연속 안정 인식을 요구한다. 등록 목표가 오인식으로 저장된 경우 요약 화면에서 즉시 수정 가능.
- 스캔 목표 오선정(최근접 코드가 내 차 기둥이 아님): 요약 화면에서 함께 인식된 다른 코드로 즉시 수정(재스캔 불필요, US1-AS3).
- 스캔이 일정 시간 코드를 확보하지 못함(저조도·비정형 표기): 수동 입력 전환 안내(US3-AS1).
- 스네이크(통로마다 역방향)·번호 리셋 등 격자 가정이 깨지는 배치: 모순 감지 → 근접확인 모드로 강등(US2-AS5). 이후 정합 관측이 누적되면 안내 모드로 복귀.
- 다른 층에서 되찾기 시도: 층 불일치 감지 → 층 이동 안내. 코드에 층 표기가 없는 주차장은 등록 시 입력받은 층으로 상기("B2에 주차하셨습니다").
- 서로 다른 층에 같은 구역·번호 존재: 층 표기(또는 별도 입력 층)로 구분.
- 앱 강제 종료/중단 후 복귀: 저장된 주차 기록으로 언제든 재시작.
- 되찾기 중 백그라운드 전환 후 복귀: 누적 관측(공간 좌표)은 무효화되어 관측 부족 상태에서 재시작("다시 주변을 비춰주세요"), 저장된 주차 기록은 유지.
- 등록 도중 미저장 이탈: 입력값이 있으면 이탈 확인 후 닫기.
- 어두운 구역: 손전등 켜기 토글 제공.
- 카메라 권한 거부: 수동 입력 등록 + 저장 정보 열람은 완전히 동작, 카메라 기능 진입 시 설정 이동 안내.

## Requirements *(mandatory)*

### Functional Requirements

**진입·등록**

- **FR-001**: 사용자는 홈 화면의 진입 버튼으로 내 차 찾기 기능을 열 수 있어야 한다. 기능은 지도 화면과 독립된 전체 화면으로 동작하며, 진입 시 활성 주차 기록이 없으면 스캔 등록 화면(권한 거부 시 수동 입력 폼)으로, 있으면 요약 화면(허브)으로 분기한다.
- **FR-001a**: 요약 화면은 기둥 코드(최대 강조)·층·경과 시간·주차 사진(탭 확대)을 표시하고, 안내 시작·완료(찾았어요)·새 위치 등록 액션을 제공해야 한다. 등록 저장 직후에도 이 화면이 저장 확인을 겸한다.
- **FR-002**: 활성 기록 없이 진입하면 카메라 스캔 등록이 시작되어야 한다. 스캔은 주변 기둥 코드와 각 코드의 공간 위치를 연속 자동 수집하고, 신뢰도 있는 코드가 1개 이상 확보되면 자동 저장한다(주차 시각 자동 기록). 오인식 확정(동일 코드 반복 관측)과 목표 선정 안정화를 위한 짧은 유예(수 초)는 허용하되, 인접 코드 수집을 위해 저장을 지연하지 않는다.
- **FR-002a**: 목표 코드는 스캔 시작 위치(사용자=차 위치) 기준 최근접 인식 코드로 자동 선정되어야 하며, 저장 직후 요약 화면에서 함께 인식된 다른 코드로 즉시 수정할 수 있어야 한다(확인 강제 없음, 재스캔 불필요). 스캔 중 공간 위치 파악에 실패한 코드만 확보된 경우에도 저장은 가능해야 하며, 이때 목표는 가장 많이 관측된 코드로 선정한다(위치 있는 코드가 하나라도 있으면 그중 최근접 우선).
- **FR-002b**: 스캔 중 함께 인식된 그 외 코드들은 목표 기준 인접 코드 관계(상대 배치·인덱스)로 자동 저장되어야 한다. 이를 위해 사용자에게 추가 행동을 요구하지 않는다.
- **FR-003**: 코드가 인식된 프레임이 주차 사진으로 자동 저장되어야 한다. 사용자는 원하면 사진을 수동으로 추가 촬영할 수 있다.
- **FR-004**: 스캔이 일정 시간 코드를 확보하지 못하면 수동 입력 전환을 안내해야 한다. 수동 입력으로 코드 입력·층 선택·사진 첨부 등록이 가능해야 하며, 저장 결과는 스캔 등록과 동일하다.
- **FR-005**: 등록되는 코드에 층 표기가 없으면 시스템은 층을 별도 필드로 확인 입력받아야 한다.
- **FR-006**: 시스템은 기둥 코드 문자열을 층/구역/번호 구조로 해석할 수 있어야 한다. 일반적 패턴(영문 구역-숫자, 한글 구역(가/나/다)-숫자, B·지하 층 접두)을 우선 지원한다.

**되찾기 — 단계적 방향 안내**

- **FR-007**: 되찾기 모드에서 시스템은 카메라에 잡힌 주변 기둥 코드를 연속적으로 인식·누적해야 한다.
- **FR-008**: 되찾기 중 인식된 텍스트 중 등록 시 확보된 코드들과 표기 형식이 일치하는 것만 방향 추정 후보로 인정해야 한다(차량 번호판·안내문 등 오검출 배제). 수동 등록 세션은 입력된 코드 1개로부터 표기 형식을 유도한다.
- **FR-009**: 방향 추정은 관측 수·구성에 따라 단계적으로 동작해야 한다: (a) 유효 코드 1개 — 방향 없음, 주변 관측 안내 (b) 2개가 한 축(구역 또는 번호)에서만 다름 — 해당 축 방향의 안내(목표가 그 축 위일 때). 목표가 그 축 위에 있지 않으면 (c)와 동일하게 부족한 축을 특정한 추가 관측 안내 (c) 2개가 두 축 모두 다름 — 방향 산출 불가, 부족한 관측을 특정한 안내 (d) 서로 다른 위치 3개 이상 — 격자 추정에 의한 방향 안내.
- **FR-010**: 방향 안내는 목표 방향 표시·대략적 거리감·추정 신뢰도를 포함해야 하며, 현재 추정 단계(관측 부족·추가 관측 안내/한 축/격자/강등/도착)가 사용자 표현에서 구분되어야 한다. 불확실할수록 "대략 이 방향" 수준으로 과신 없이 표현한다.
- **FR-011**: 새로운 코드가 인식되거나 기존 코드가 재인식되면 방향 추정이 갱신·보정되어야 한다.
- **FR-012** *(설계 개정 v2 — 260911 교차 검증 반영)*: 방향 안내의 자기 검증은 **3중 가드**로 수행한다: ① **외삽 가드** — 목표가 관측 배치에서 지나치게 먼 외삽이면 화살표를 표시하지 않음 ② **간격 타당성 가드** — 추정된 축의 스텝당 간격이 물리적 타당 범위를 벗어나면 기각 ③ **거리 상한 가드** — 주차장 물리 규모를 넘는 목표 거리는 표시하지 않음. 가드 위반 시 화살표 대신 그라디언트 힌트/추가 관측 안내로 강등한다. 잔차 기반 모순 감지는 **충분한 관측(과결정 상태)에서만** 병행한다 — 관측 3개의 정확결정계에서는 잔차가 항상 0이라 단독 감지 수단이 될 수 없음(개정 사유). 일관된 관측이 누적되면 방향 안내로 복귀할 수 있어야 한다. 강등·관측 부족 상태에서는 확정 관측의 구역·번호를 이용한 **그라디언트 힌트**를 제공한다 — 같은 구역이면 번호 대소·추이("가까워지고 있어요"), 다른 구역이면 **구역 차이의 크기만**("약 N개 구역 차이" — 구역 글자 순서와 보행 방향의 정렬은 미검증 가정이므로 방향 어휘는 사용하지 않음).
- **FR-013**: 저장된 목표 코드가 연속적으로 안정 인식되면 시스템은 "도착"을 확정 표시해야 한다. 일시적 오인식 한 번으로 확정되어서는 안 된다.
- **FR-013a**: 등록 시 저장된 인접 코드가 되찾기 중 인식되면 차량 근접 신호로 활용되어야 한다(추정 신뢰도 상승·도착 판단 보조). 저장된 배치 전체를 현재 관측에 정렬하는 본격 매칭은 범위 밖(Later).
- **FR-014**: 인식된 코드의 층이 저장된 층과 다르면 층 이동 안내를 표시해야 한다. 코드에 층 표기가 없는 주차장에서는 등록 시 입력받은 층을 상기시켜야 한다.
- **FR-015**: 코드는 인식되었으나 공간 위치 파악에 실패한 경우, 해당 코드를 층 확인·도착 확정에는 활용하되 방향 추정에는 포함하지 않아야 하며, 실패 반복 시 개선 행동(더 가까이, 손전등)을 안내해야 한다. 공간 추적 품질이 저하되면 사용자에게 상태와 개선 행동을 안내해야 한다.

**폴백·환경**

- **FR-016**: 자동 방향 안내가 불가능한 모든 상황(코드 체계 해석 실패, 카메라 사용 불가 등)에서 사용자는 저장된 사진과 코드 텍스트를 폴백으로 확인할 수 있어야 한다. 요약 화면(FR-001a)이 이 폴백 역할을 겸한다. 구역·번호를 해석할 수 없는 코드로 등록된 세션에서 안내를 시작하면, 격자 안내 없이 목표 코드 직접 인식(도착 확정)과 층 상기만 제공하는 근접확인 모드로 동작한다.
- **FR-017**: 카메라 권한이 거부된 상태에서도 수동 입력 등록과 저장 정보 열람은 완전히 동작해야 하며, 카메라 기능 진입 시 설정 이동을 안내해야 한다.
- **FR-018**: 등록·되찾기 카메라 화면에서 손전등을 켜고 끌 수 있어야 한다.

**세션·프라이버시**

- **FR-019**: 활성 주차 기록은 동시에 1개만 유지되며, 새 등록 시 기존 기록은 사용자 안내 후 대체되어야 한다.
- **FR-020**: 저장된 주차 기록(코드·층·사진·주차 시각·경과 시간)은 앱 재실행 후에도 유지되고 언제든 열람 가능해야 한다.
- **FR-021**: 사용자는 도착 확정 또는 수동 완료("찾았어요")로 주차 기록을 종료할 수 있어야 한다. 완료된 기록은 최근 1건만 보관하고 이전 기록(사진 포함)은 삭제한다.
- **FR-022**: 카메라 영상은 저장되지 않아야 하며, 저장된 코드·사진은 앱 내부 저장소에만 보관된다 — 사진 라이브러리에 저장하지 않고, 앱 삭제 시 함께 삭제되며, 외부 전송이 없다. 자동 저장 사진에 타인 차량·인물이 우연히 포함될 수 있으므로 로컬 한정 보관과 기록 완료 시 삭제(FR-021)로 노출을 최소화한다.

**개발 지원 (기본 비활성, 출시 빌드 포함)**

- **DR-001**: 카메라 화면 위에 공간 디버그 시각화를 제공해야 한다 — 실시간 텍스트 인식 박스(채택/기각 색상 구분+기각 사유), 인식 코드의 공간 위치 라벨(신뢰도 구분), 추정 격자 축과 외삽 격자점, 목표 예측 위치, 예측-관측 어긋남(잔차) 표시, 이동 궤적. 스캔 등록과 되찾기 양쪽에서 동작해 파이프라인(인식→채택/기각→앵커→격자→방향)의 처리 과정을 눈으로 검증할 수 있어야 한다.
- **DR-002**: 비공간 상태(추정 단계, 후보 기각 사유, 관측 수, 신뢰도 수치)를 화면 한쪽에 텍스트로 표시해야 한다.
- **DR-003**: 되찾기 세션의 관측 이벤트(인식 텍스트, 공간 위치, 추적 상태·실패 이벤트, 시각)와 **기기 포즈(위치·방향) 및 표시된 안내 값(화살표 각도·상태)** 을 파일로 기록하고, 기록을 재생해 **추정 로직 계층**(파싱·채택/기각·격자 피팅·모순 감지·상태 전이·화살표 각도 산출)을 재현·검증할 수 있어야 한다. 모든 좌표는 세션 좌표계 안에서 자기완결적이므로 재생 검증에 현장이 필요하지 않다. 카메라 영상은 기록하지 않으므로 지각 계층(문자 인식·공간 위치 획득 자체)의 재실행은 범위 밖이며, 로그의 실패 이벤트로 진단만 지원한다.
- **DR-004**: 추정 단계 전이, 강등 발생, 후보 기각 사유는 로그로 기록되어야 한다(단계별 검증 기준).
- **DR-005**: 디버그 기능(DR-001~003)은 출시 빌드를 포함한 모든 빌드에 포함되되 **기본 비활성** 상태여야 하며, 개발자 메뉴 또는 히든 제스처(특정 입력)로 켜고 끌 수 있어야 한다. 활성화하면 프로덕션 UI를 가리지 않는 오버레이 레이어로 표시된다. 진입 방식은 일반 사용자가 우연히 발견하기 어려워야 하고, 비활성 상태에서는 성능·배터리에 영향을 주지 않아야 한다.

### Key Entities

- **주차 기록(Parking Session)**: 한 번의 주차를 나타냄. 목표 기둥 코드, 층(코드 내 표기 또는 별도 입력), 해석된 구역/번호, 자동 저장된 사진(코드 인식 프레임), 주차 시각, 스캔 부산물로 저장된 인접 코드 관계(목표 기준 상대 배치·인덱스), 상태(활성/완료). 위치 좌표는 저장하지 않는다(세션 간 재사용 불가).
- **기둥 코드(Pillar Code)**: 주차장 기둥 표지판의 위치 라벨(예: B2-A-3). 층/구역/번호 토큰으로 구성. 되찾기 중 인식된 코드들은 관측 위치와 함께 누적되어 방향 추정의 입력이 된다.
- **방향 추정 상태(Guidance State)**: 관측 부족 → 한 축 안내 → 격자 안내 → (모순 감지 시) 근접확인 강등 → 도착의 단계를 갖는 상태. 사용자 표현과 디버그 표시의 기준.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 일반 조명의 지하주차장에서 스캔 등록이 진입 후 15초 이내에 자동 완료된다(사용자 행동은 "주변 훑기"뿐). 수동 폴백 등록은 30초 이내에 완료할 수 있다.
- **SC-002**: 일반 조명의 지하주차장에서 3m 이내 정면 표지판 기준, 기둥 코드 인식이 90% 이상 성공한다.
- **SC-003**: 방향 산출이 가능한 관측(같은 축 2개 또는 3개 이상)이 갖춰진 시점부터 5초 이내에 방향 안내가 표시된다.
- **SC-004**: 규칙적 격자 배치의 주차장에서 방향 안내를 따라간 사용자의 90% 이상이 추가 도움 없이 차량에 도달한다(도착 확정 기준, 풀 경험 기기 기준 — Assumptions 참조).
- **SC-005**: 불규칙 번호 배치의 주차장에서, 추정과 어긋나는 관측이 발생하면 다음 코드 인식 시점 이후로 잘못된 방향 표시가 유지되지 않는다(근접확인 모드로 전환).
- **SC-006**: 차량 번호판 등 코드가 아닌 텍스트가 방향 안내를 왜곡하는 사례가 현장 시험에서 0건이다.
- **SC-007**: 자동 안내가 실패하는 경우에도 사용자는 2번의 탭 이내에 저장된 사진·코드 폴백 화면에 도달할 수 있다.
- **SC-008**: 앱 종료·재실행 후에도 주차 기록이 100% 보존된다.
- **SC-009**: 현장에서 발생한 **추정 로직 오류**(방향 산출·강등 판단·채택/기각)는 기록 재생만으로 책상에서 재현할 수 있다(디버그 도구 활성 시, 출시 빌드 포함). 지각 계층 문제(인식 실패·앵커 오배치)는 기록된 실패 이벤트로 발생 빈도·상황을 진단할 수 있다.

## Assumptions

- 대상 주차장은 기둥마다 위치 코드 표지판이 부착된 일반적인 한국 대형 건물 지하주차장이다. 표지판이 없는 주차장은 사진 폴백으로만 지원한다.
- 이 기능은 절대 실내 측위가 아니라 점진적 방향 추정이며, "정확한 안내"가 아니라 "정직한 안내"를 지향한다. 격자 가정이 깨지는 주차장에서 근접확인 모드로 강등되는 것은 실패가 아니라 정상 동작이다.
- 주차한 층까지의 이동(엘리베이터 등)은 사용자가 직접 수행한다. 멀티층 자동 경로 안내는 범위 밖이다.
- 활성 주차 기록은 항상 1개다(차량 여러 대 동시 관리 비범위).
- 사전 실내지도, 비콘 등 외부 인프라·데이터는 일절 사용하지 않는다. 모든 데이터는 기기 내에만 저장된다.
- 지도 화면과의 연동은 없다(지하는 위성 신호 음영 지역). 독립 전체 화면 모듈로 동작한다.
- 고정밀 깊이 인식이 가능한 기기(Pro 계열)를 풀 경험 기준으로 하며, 그 외 기기는 공간 위치 파악 성공률 저하를 전제로 폴백 경로 중심으로 성립하면 정상 범위로 본다. 성공 기준(SC-004)은 풀 경험 기기 기준이다.
- 인접 코드의 수집(스캔 부산물)과 근접 신호 활용은 MVP에 포함된다. 저장된 배치 전체를 현재 관측에 정렬하는 본격 매칭 알고리즘, 빈자리 안내, 옥외 주차 확장은 이번 범위에서 제외한다(Later).
