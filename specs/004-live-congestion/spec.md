# Feature Specification: 실시간 도시 혼잡 지도 (Live City Pulse)

**Feature Branch**: `004-live-congestion`

**Created**: 2026-06-22

**Status**: Draft

**Input**: User description: "지도에 서울 주요 장소의 실시간 혼잡도를 색으로 띄우고, 슬라이더로 지금→향후 12시간 예측을 돌려본다. 혼잡도와 예측은 서울 실시간 공공데이터가 직접 제공(자체 전처리·예측 모델 없음). '지금 어디가 붐비나, 1시간 뒤엔?'을 라이브로 답한다."

## 핵심 방향 *(context)*

제품 방향은 **도보 메인 + 살아있는 데이터 지도**다. 실시간 혼잡 지도는 도시의 "지금 맥박"을 보여주는 라이브 레이어로, 사용자가 **시간 슬라이더를 지금에서 가까운 미래로 밀어** 주요 장소들이 얼마나 붐비고 한산해질지를 본다. 혼잡 단계와 예측은 **서울 실시간 공공데이터가 직접 제공**하므로 앱은 받아서 보여줄 뿐, 별도 전처리나 예측 모델이 없다. 신규 화면이 아니라 홈 지도에 **실시간 레이어 + 시간 컨트롤 드로어** 한 쌍을 얹는 "모드"다. (핀 인사이트가 점 단위 정보라면, 이건 도시 전체의 실시간 맥동이다.)

## Clarifications

### Session 2026-06-22

- Q: 진입 시 ~120개 장소 데이터를 어느 범위로 로딩하나(호출량·안정성)? → A: 보이는 지도 영역의 장소만 우선 로딩하고, 카메라 이동 시 그 영역을 추가 로딩(+짧은 TTL 캐시)
- Q: MVP에서 혼잡을 어떤 형태로 그리나(마커 vs 면)? → A: 장소 마커(혼잡 단계색) — citydata POI 구조와 일치, 좌표만으로 구현. 면 색칠은 Later
- Q: 같은 화면에서 자동 주기 갱신을 넣나? → A: 수동만 — 새로고침 버튼 + TTL(원천 주기 ≈5분) 만료 시 재요청, 기준 시각 노출로 신선도 표시. 자동 타이머 갱신은 Later

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 지금 어디가 붐비나 (실시간 혼잡 레이어) (Priority: P1)

사용자가 홈 지도에서 실시간 혼잡 버튼을 누르면, 서울 주요 장소들이 **혼잡 단계별 색**(붐빔/약간붐빔/보통/여유)으로 지도에 표시된다. 한눈에 "지금 어디가 사람이 많고 어디가 한산한지"를 본다. 표시 기준 시각도 함께 보여 신선도를 알 수 있다.

**Why this priority**: 이 기능의 본질. 이 스토리만으로 "도시의 지금 혼잡을 라이브로 본다"는 핵심 가치가 완성된다(MVP).

**Independent Test**: 혼잡 버튼 진입 → 주요 장소들이 혼잡 단계 색으로 표시되고 기준 시각이 보이는지, 종료 시 원래 홈으로 복원되는지로 단독 검증.

**Acceptance Scenarios**:

1. **Given** 홈 지도 상태, **When** 실시간 혼잡 버튼을 탭하면, **Then** 주요 장소들이 혼잡 단계 색으로 표시되고 하단에 시간 컨트롤 드로어가 올라온다.
2. **Given** 혼잡 모드, **When** 표시를 보면, **Then** 각 장소의 혼잡 단계가 색으로 구분되고 "기준 시각"(예: 14:30)이 노출된다.
3. **Given** 진입 시 정류소·따릉이 레이어가 켜져 있던 상태, **When** 혼잡 모드에 진입하면, **Then** 겹침을 막기 위해 그 레이어들이 자동으로 꺼진다.
4. **Given** 혼잡 모드, **When** 종료(드로어 닫기)하면, **Then** 혼잡 레이어가 사라지고 진입 전 레이어 상태·홈 드로어·지도 영역이 복원된다.
5. **Given** 일부 장소의 데이터를 받지 못한 상태, **When** 화면을 보면, **Then** 받은 장소만 표시되고 데이터 없는 곳은 색칠되지 않는다(0으로 오인 없음).

---

### User Story 2 - 가까운 미래로 돌려보기 (지금→+12h 예측 슬라이더) (Priority: P2)

사용자가 시간 슬라이더를 밀면 "지금"에서 "향후 N시간"으로 이동하며, 각 장소의 색이 그 시각의 **예측 혼잡 단계**로 바뀐다. "지금은 붐비는데 2시간 뒤엔 빠지나?"를 손가락으로 확인한다. 예측값은 공공데이터가 제공하는 시간별 예측을 그대로 사용한다.

**Why this priority**: 라이브 현재 위에 얹는 "가까운 미래" — 의사결정(지금 갈까/이따 갈까)에 직접 쓰이는 핵심 차별점. 현재 표시가 되면 예측 스크럽은 같은 데이터의 시간축 이동이다.

**Independent Test**: 슬라이더를 미래 시각으로 이동했을 때 각 장소 색이 그 시각 예측으로 바뀌고, 지금으로 되돌리면 실시간 값으로 복귀하는지로 단독 검증.

**Acceptance Scenarios**:

1. **Given** 혼잡 모드(지금 기준), **When** 슬라이더를 +N시간으로 이동하면, **Then** 각 장소 색이 그 시각의 예측 혼잡 단계로 갱신된다.
2. **Given** 미래 시각을 보는 중, **When** 슬라이더를 "지금"으로 되돌리면, **Then** 실시간 혼잡 값으로 돌아온다.
3. **Given** 어떤 장소의 예측 데이터가 제공 범위보다 짧은 경우, **When** 그 범위를 넘는 시각으로 이동하면, **Then** 슬라이더가 제공 가능한 범위까지만 동작하거나 해당 장소를 중립 처리한다.

---

### User Story 3 - 장소 상세 예측 곡선 (Priority: P3)

사용자가 혼잡한 장소(마커)를 탭하면, 그 장소의 **실시간 혼잡 + 향후 시간별 예측 곡선**을 본다. "이 장소가 몇 시에 가장 빠질지"를 한눈에 본다.

**Why this priority**: 지도 색이 "어디가 붐비나"라면, 곡선은 "이 장소가 시간에 따라 어떻게 변하나"를 보여줘 깊이를 더한다. 핵심 레이어와 독립적.

**Independent Test**: 한 장소를 탭 → 그 장소의 실시간 값 + 예측 곡선이 표시되는지로 단독 검증.

**Acceptance Scenarios**:

1. **Given** 혼잡 모드, **When** 지도에서 한 장소를 탭하면, **Then** 그 장소의 실시간 혼잡과 향후 예측 곡선이 표시된다.
2. **Given** 상세가 표시된 상태, **When** 데이터에 기준 시각이 있으면, **Then** 곡선에 신선도(기준 시각)가 함께 표시된다.

---

### Edge Cases

- **데이터 일부/전체 실패**: 일부 장소만 받으면 받은 것만 표시; 전체 실패 시 "지금은 데이터를 불러올 수 없음" 안내 + 재시도 유도.
- **예측 범위 부족**: 제공 예측이 슬라이더 최대보다 짧으면 가능한 범위까지만 활성(또는 그 시각 중립).
- **커버리지 밖 지역**: 데이터가 없는 지역은 표시하지 않음(빈 곳은 "데이터 없음"으로 정직하게).
- **모드 중 네트워크 끊김**: 마지막으로 받은 값 + 기준 시각을 유지 표시하고 새로고침을 유도.
- **신선도**: 항상 표시 기준 시각을 노출해 오래된 값이 현재처럼 오인되지 않게 함.
- **위성 지도 위 가독성**: 진입 시 표준 지도로 고정.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 사용자는 홈 지도에서 **전용 버튼**으로 실시간 혼잡 모드에 진입할 수 있어야 한다(따릉이/버스 레이어 메뉴와 분리된 시그니처 진입점).
- **FR-002**: 시스템은 서울 주요 장소들의 **실시간 혼잡 단계**를 지도에 **장소 위치의 단계별 색 마커**로 표시해야 한다(MVP는 마커 형태; 면 색칠은 Later).
- **FR-003**: 시스템은 항상 표시값의 **기준 시각(신선도)** 을 사용자에게 노출해야 한다.
- **FR-004**: 시스템은 하단 드로어에 **지금 → 향후 약 12시간** 범위의 시간 슬라이더를 제공하고, 이동 시 각 장소 색을 그 시각의 **예측 혼잡 단계**로 갱신해야 한다.
- **FR-005**: 예측은 **공공데이터가 제공하는 시간별 예측을 그대로** 사용해야 하며, 앱이 자체 예측 모델을 만들지 않는다.
- **FR-006**: 사용자가 장소(마커)를 탭하면 그 장소의 **실시간 혼잡 + 예측 곡선**을 볼 수 있어야 한다.
- **FR-007**: 시스템은 **수동 새로고침**을 제공하고, **TTL(원천 갱신 주기 ≈5분) 만료 시 재요청**으로 신선도를 유지해야 한다. 기준 시각을 노출해 값이 오래됐는지 알 수 있어야 한다. (같은 화면 자동 타이머 갱신은 Later)
- **FR-007a**: 시스템은 **현재 보이는 지도 영역의 장소만 우선 로딩**하고, 카메라 이동 시 새로 들어온 영역의 장소를 추가 로딩해야 한다(짧은 TTL 캐시로 재요청 최소화). 전체 일괄 호출은 하지 않는다.
- **FR-008**: 혼잡 모드 진입 시 정류소·따릉이 등 **겹치는 POI 레이어는 자동으로 꺼지고**, 종료 시 진입 전 상태로 복원되어야 한다(레이어 토글 설정 자체는 보존).
- **FR-009**: 혼잡 모드 진입 시 지도는 **표준 지도로 고정**되고 **현재 보던 영역(카메라)을 유지**해야 한다.
- **FR-010**: 종료 시 혼잡 레이어는 제거되고 홈 드로어(검색바)가 복귀해야 한다.
- **FR-011**: 데이터를 받지 못한 장소·커버리지 밖 지역은 **표시하지 않거나 중립 처리**하여 "여유 0명"처럼 오인되지 않아야 한다.
- **FR-012**: 데이터 일부 실패에도 **받은 장소는 정상 표시**(부분 실패 허용)되어야 하며, 전체 실패 시 사용자에게 상태를 안내해야 한다.
- **FR-013**: 혼잡 단계 색은 **색각·명도 접근성(WCAG 고려)** 을 만족하고 디자인 토큰을 경유해야 한다.
- **FR-014**: 데이터·출처는 **서울 공공데이터**만 사용해야 한다(라이선스 준수, 출처 표시).

### Key Entities *(include if feature involves data)*

- **혼잡 장소(Congestion Place)**: 서울 주요 장소 1곳. 위치(좌표/이름), **실시간 혼잡 단계**, **시간별 예측 시계열**(향후 N시간), 데이터 기준 시각. 표시 색과 상세 곡선의 원천.
- **시간 상태(Timeline State)**: 현재 슬라이더 오프셋(지금=0, 미래=+N시간)과 새로고침/로딩 상태. 오프셋이 바뀌면 각 장소의 표시 색이 실시간↔예측으로 전환된다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자는 홈에서 **2번 이내 탭**으로 실시간 혼잡 모드에 진입해 주요 장소의 혼잡 색을 볼 수 있다.
- **SC-002**: 슬라이더로 시각을 바꾸면 장소 색이 **0.3초 이내**에 체감상 즉시 갱신된다(이미 받은 예측 기준).
- **SC-003**: 표시 화면에는 항상 **기준 시각이 노출**되어, 사용자가 값의 신선도를 알 수 있다.
- **SC-004**: 데이터 **일부 실패 시에도 받은 장소는 정상 표시**되며, 빈 지역이 "여유 0"으로 오인되는 사례가 없다.
- **SC-005**: 혼잡 모드 종료 후 홈의 레이어 상태·드로어·지도 영역이 **진입 전과 동일**하게 복원된다.
- **SC-006**: 슬라이더는 **지금(0)부터 공공데이터가 제공하는 예측 범위(약 +12시간)** 까지 이동할 수 있다.

## Assumptions

- **MVP 범위**: 실시간 혼잡 마커 레이어(FR-001~003) + 지금→+12h 예측 슬라이더(FR-004,005) + 장소 상세 곡선(FR-006) + 신선도/수동새로고침/복원(FR-007~012). 영역(면) 색칠, **자동 주기 갱신**, 자동 타임랩스 재생, 대기질·따릉이 흐름 결합, 도보 경로 "혼잡 회피" 연계는 **Later**.
- **데이터 성격**: 혼잡 단계·예측 모두 **실시간 공공데이터가 직접 제공**(앱은 받아서 표시만). 자체 전처리·임베딩·예측 모델 없음.
- **커버리지**: 전 지역이 아니라 **공공데이터가 다루는 주요 장소(약 120곳)**. 나머지는 "데이터 없음"으로 정직하게 둔다.
- **신선도/캐시**: 라이브 특성상 네트워크가 필요하나, 짧은 주기 캐시로 반복 진입을 빠르게 하고 기준 시각을 노출한다. 오프라인 시 마지막 캐시값 + 기준 시각 표시.
- **로딩 범위**: 진입/이동 시 **보이는 지도 영역의 장소만** 받는다(전체 일괄 호출 회피 → 호출량·지연·부분실패 위험 감소). 카메라 이동 시 새 영역 추가 로딩 + TTL 캐시.
- **표현 방식**: **장소 마커(혼잡 단계색)** 확정(Clarifications). 면(영역) 색칠은 장소 경계/반경 확보 시 Later.
- **데이터 검증 잔여(plan 단계 스파이크)**: 예측 시계열의 정확한 시간 범위·간격·개수, 장소 좌표 포함 여부(없으면 장소명→좌표 소량 매핑), 전체 장소 조회의 호출량·안정성 전략은 실데이터 1회 확인으로 확정한다.
- **신규 화면 없음**: 홈 지도 위 모드 전환(라이브 레이어 + 시간 드로어). 기존 드로어 스왑·레이어 토글·상세 팝업 패턴을 재사용한다.
