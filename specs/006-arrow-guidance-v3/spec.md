## 배경 요약

005에서 구현한 방향 안내는 세 번의 수정(신선도 컷 → 다중 표지판 제외 → v2 3중 가드)을 거치며 안전해졌으나, 260919 현장 세션에서 **화살표 가동률 0%**(123초, 관측 176건, 위치 확보 74%)에 도달했다. 원인은 두 가지가 겹친 것이다:

1. 동일 코드 다중 표지판 제외가 '3'행 코드(F3·G3·H3·J3)를 전부 제거 → 목표 J5의 번호 축 불성립
2. 남은 추정도 외삽 레버 4.77(상한 2.5)로 차단

추가로 교차 리뷰가 실측으로 확인한 두 결함:

3. **G2 간격 상한 15m가 오설정** — 이 주차장의 정상 구역 피치가 16.0~16.9m/스텝이라 정상 격자가 기각된다. 즉 ①을 고쳐도 가동률은 0%로 남는다
4. **축외 목표를 스텝 수로 제한하는 방식은 원리적으로 각도를 보장하지 못한다** — 세션 종료 시점 기기가 J4에서 3.5m인데 미지 번호축 피치는 4.6~5.0m로, 목표에 가까울수록 방위 오차가 최대 180°까지 열린다

이 기능은 "화살표를 숨겨 안전을 얻는" v2의 방식을 **"방향을 보장할 수 있을 때 표시하고, 확신의 정도를 정직하게 드러내는"** 방식으로 교체한다.

## Clarifications

### Session 2026-09-20

- Q: 정확도를 어떻게 표현하는가 → A: **%로 표시**(상한 95%, 100% 미표시). 3단 등급은 내부 구간으로만 사용
- Q: 축외 목표에 화살표를 어디까지 허용하는가 → A: 스텝 수 컷이 아니라 **측방 각도 불변량** `asin(측방 불확실성 U / 보수적 거리 하한 d⁻) ≤ θmax` (U는 미지 축 오프셋 + 적합 불확실성 + 팽창의 합 — PR #58 리뷰 반영)
- Q: 화살표가 닫히는 근접 구간은 무엇으로 안내하는가 → A: **미니맵 접힘 라이브 + 근접 카드**(각도 보장 상실 지점 = 근접 모드 전환점으로 통합)
- Q: 다중 표지판 코드를 어떻게 다루는가 → A: 제외 대신 **인스턴스 클러스터로 분리 수용**, 표본 2개 이상 클러스터만 채택
- Q: 오래된 관측을 어떻게 다루는가 → A: 제외 대신 **불확실성 팽창**(% 점수·표시에만 반영, 점추정 오염 금지)
- Q: 005와의 관계 → A: 005 **스펙은 동결**(새 요구사항을 005에 추가하지 않음), 006이 되찾기 안내 관련 FR을 **대체**(아래 매핑 표). 등록·세션·프라이버시·디버그 FR은 005 유지. 다만 005의 미완 태스크(T045 임계값 튜닝·T048 최종 회귀)는 **006의 P2·P5로 승계**한다 — 006의 캘리브레이션과 현장 검증이 동일 작업을 수행하므로 별도 잔여로 남기지 않는다

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 기둥 두세 개로 방향을 얻는다 (Priority: P1)

주차장에 들어선 사용자가 카메라로 주변 기둥을 비춘다. 두 번째 기둥이 인식되는 순간, 방향을 보장할 수 있다면 화살표가 나타난다. 화살표 옆에는 지금 이 안내가 얼마나 믿을 만한지가 %로 붙어 있고, 정확도가 낮은 동안에는 화살표가 점선이며 거리는 표시되지 않는다. 기둥을 더 비출수록 %가 오르고 화살표가 실선으로 바뀌며 거리가 나타난다.

**Why this priority**: 이 기능의 존재 이유. 260919에서 완전히 상실된 경험이며, 나머지 스토리는 이것의 보조다.

**Independent Test**: 260919·260911·260801 현장 로그 리플레이에서 화살표 가동률과 표시 %의 변화를 측정. 실기기에서는 기둥 2개 인식 후 화살표 등장까지의 시간으로 확인.

**Acceptance Scenarios**:

1. **Given** 같은 번호 행의 기둥 2개(F4·H4)를 인식했고 목표가 J5, **When** 측방 각도 `asin(U/d⁻)`가 θmax 이하, **Then** 점선 화살표와 낮은 %가 표시되고 거리는 표시되지 않는다
2. **Given** 위 상태, **When** 다른 번호 기둥(J3)이 인식되어 두 축이 성립, **Then** %가 오르고 화살표가 실선으로, 거리가 "약 Nm"로 표시된다
3. **Given** 화살표 표시 중, **When** 목표에 근접해 각도 보장이 무너짐, **Then** 화살표가 사라지는 대신 근접 모드(미니맵·카드)로 전환된다
4. **Given** 추정된 축 간격이 부조리 범위(0.5m 미만 또는 25m 초과), **When** 추정이 갱신됨, **Then** 화살표를 표시하지 않고 추가 관측을 안내한다
5. **Given** 관측 구역(B~D)에서 여섯 스텝 떨어진 목표(J)로 외삽 중이라 적합 불확실성이 큼, **When** 측방 각도가 θmax를 초과, **Then** 잔차가 0에 가깝더라도 화살표를 표시하지 않는다(260911 J21 102m 사례)

### User Story 2 - 왜 더 비춰야 하는지가 보인다 (Priority: P2)

사용자는 화면 구석의 작은 원형 미니맵에서 자신(중심)과 인식한 기둥들, 그리고 목표의 불확실성 영역을 본다. 축이 하나만 성립한 동안 목표는 길쭉한 띠로 보이고, 기둥을 더 비출수록 띠가 원으로, 원이 점으로 조여든다. 상단에는 "같은 구역의 다른 번호 기둥을 비추면 정확도가 올라가요" 같은 행동 지시가 함께 표시된다.

**Why this priority**: %가 "수치의 상승"을 말한다면 미니맵은 "공간의 수렴"을 보여준다. 각도 보장이 닫히는 근접 구간에서는 주 안내 역할을 겸하므로 선택 사항이 아니다.

**Independent Test**: 시뮬레이터에서 합성 관측을 주입해 띠→원→점 전환과 접힘/펼침 전환을 확인. 행동 지시는 상태별 문구 단위 테스트.

**Acceptance Scenarios**:

1. **Given** 한 축만 성립, **When** 미니맵이 표시됨, **Then** 목표가 축 방향으로 길쭉한 띠로 그려진다
2. **Given** 두 축 성립, **When** 관측이 추가됨, **Then** 띠가 원으로 바뀌고 관측이 늘수록 반경이 줄어든다
3. **Given** 접힘 상태, **When** 사용자가 탭, **Then** 같은 그림이 확대되며 코드 라벨·눈금·이동 자취가 추가된다
4. **Given** 추가 관측이 필요한 상태, **When** 그라디언트 힌트가 존재, **Then** 힌트와 축 행동 지시가 **함께** 전달된다(하나가 다른 하나를 가리지 않는다)

### User Story 3 - 등록이 나중의 정확도를 만든다 (Priority: P3)

주차 직후 스캔 등록 화면에서, 사용자는 목표 기둥 외에 주변 기둥을 몇 개 더 비추면 나중에 찾기 쉬워진다는 안내와 진행 표시("인접 1/3")를 본다. 저장은 지금처럼 즉시 가능하다.

**Why this priority**: 260919 세션은 스캔 10초·인접 0개로 저장되어 되찾기 정확도의 상한이 등록 시점에 이미 정해졌다. 비용이 낮고 효과가 상류에 있다.

**Independent Test**: 등록 세션 로그의 인접 코드 확보 수 분포를 유도 도입 전후로 비교.

**Acceptance Scenarios**:

1. **Given** 스캔 중 목표만 확보, **When** 자동 저장 유예 구간, **Then** 인접 확보 유도 문구와 진행 표시가 나타난다
2. **Given** 유도 표시 중, **When** 사용자가 저장을 진행, **Then** 지연이나 차단 없이 저장된다

### Edge Cases

- 목표가 관측 배치에서 매우 멀어 표시 거리가 관측 스팬을 크게 초과 → 방향만 모드(거리 숨김), 화살표 유지
- 같은 코드가 세 곳 이상에서 관측 → 각 인스턴스를 독립 클러스터로 유지, 표본 1개 클러스터는 격자에서 제외
- 관측이 모두 오래되어 팽창이 커짐 → % 하락과 미니맵 원 확대로 표현, 화살표는 각도 보장이 유지되는 한 존속
- 공간 추적 재시작(리로컬라이즈 실패) → 기존 관측 무효화 시 **표지판 클러스터·축 추정·팽창 상태도 함께 초기화**된다(좌표계가 달라졌으므로 이전 클러스터는 재사용 불가). 005 FR-015의 무효화 규칙을 승계한다
- 층 이동 중 다른 층 코드 관측 → 격자·클러스터에 편입하지 않는다(005 FR-014의 층 불일치 안내 우선). 층이 바뀌면 관측 집합을 무효화 대상으로 본다
- 목표 코드 직접 인식으로 도착 확정 → % 표시와 무관하게 도착이 우선(005 FR-013 유지)
- 인스턴스 조합이 프레임마다 뒤바뀜 → 선택 이력의 잦은 변경은 백분율 감점으로 반영하고, 표시 형태 전환은 히스테리시스로 억제

## Requirements *(mandatory)*

### Functional Requirements

**방향 안내 — 표시 조건과 정확도**

- **FR-101**: 화살표는 **방향을 보장할 수 있을 때 표시**되어야 한다. 보장 기준은 **측방 각도 불변량**이다 — 목표 점추정의 **측방 불확실성 U**(시선에 수직인 성분)를 **보수적 거리 하한 d⁻**로 나눈 각도 `asin(U / d⁻)`가 임계 θmax 이하일 때 표시한다. `d⁻ ≤ U`이면 보장 실패로 간주한다. 스텝 수·관측 수에 의한 표시 제한은 두지 않으며, 한 축만 성립한 상태(관측 2개)에서도 이 조건을 만족하면 표시한다.
  - **U의 구성(모두 합산)**: ① **미지 축 오프셋** — 목표가 관측된 축 밖에 있을 때 (미지 축 스텝 수) × (그 축 피치) ② **적합 불확실성** — 외삽 레버에 비례하는 측방 성분(두 축이 모두 성립해도 0이 아니다) ③ **팽창** — 관측 노화분(FR-108). 두 축이 모두 성립하면 ①이 0이 되지만 ②③은 남으므로 불변량은 항상 유효하다.
  - **미지 축 피치의 출처(등방성 가정 금지)**: 세션 중 그 축이 한 번이라도 추정된 적 있으면 그 값을, 없으면 **축별 사전 분포의 상한**(보수값)을 사용한다. 관측된 다른 축의 피치를 그대로 대입하지 않는다 — 실측에서 같은 주차장의 구역축 16.4m와 번호축 4.8m가 3.4배 차이였다.
  - **d⁻의 정의(순환 의존 차단)**: 추정 거리 d̂를 그대로 쓰지 않고 시선 방향 불확실성을 뺀 하한 `d⁻ = max(0, d̂ − U∥)`를 사용한다. 추정이 멀수록 불변량이 쉬워지는 역방향 단조성을 제거하기 위함이다.
- **FR-102**: 화살표 표시가 불가능해지는 지점(각도 보장 상실)은 **근접 모드 전환점**으로 취급되어야 한다. 화살표를 단순히 숨기는 것이 아니라 미니맵·근접 카드·힌트가 주 안내를 이어받는다.
- **FR-103**: 시스템은 현재 안내의 신뢰 정도를 **백분율로 표시**해야 한다. 값은 관측 수·외삽 레버·관측 신선도·잔차(과결정 상태에서만)·인접 코드 목격에서 산출한 연속 점수이며, **상한 95%로 100%는 표시하지 않는다**. 표시 형태는 백분율 구간에 연동된다: 낮은 구간은 점선·반투명 화살표와 거리 숨김, 중간 이상은 실선 화살표와 근사 거리("약 Nm"). 구간 경계에서의 깜빡임을 막기 위한 이력(히스테리시스)을 둔다.
- **FR-104**: 백분율 산출은 다음 한계를 명시적으로 방어해야 한다: ① 정확결정계(관측이 최소 수량인 상태)에서 잔차는 항상 0이므로 **만점이 아니라 미정보로 처리**한다 — 미정보 성분은 점수 집계에서 제외하고, 그만큼 **상한을 낮춘다**(잔차가 무정보인 상태는 중간 구간 이상으로 올라갈 수 없다) ② 공분산 기반 점수는 드리프트·다중 표지판 같은 연관 오류를 감지하지 못하므로 백분율은 하한 보장이 아니라 정직한 추정이다. **안내의 하한은 전적으로 FR-101의 측방 각도 보장이 담당한다**(백분율에 위임하지 않는다).
  - **관측 수 게이트(명시)**: 상위 구간(실선·거리 표시)은 채택 관측 3개 이상, 최상위 구간은 5개 이상 + 잔차 정보 있음 + 인접 코드 목격을 요구한다.
- **FR-105**: **간격 타당성**은 안전망이 아니라 **위생 검사**다 — 추정 축의 스텝당 간격이 명백한 부조리 범위(0.5m 미만 또는 25m 초과)면 표시하지 않고, 그 바깥의 경계 구간(실측 정상 1.5~17m/스텝을 벗어나되 부조리는 아닌 값)은 **백분율 감점**으로 처리한다. 좁은 상한으로 정상 격자를 기각하거나(실측 16.9m/스텝 사례), 실패 사례(21.5m/스텝)와 근소한 마진으로 안전을 의존해서는 안 된다. **화살표 차단의 실질적 책임은 FR-101이 진다.**
- **FR-106**: 표시 거리의 상한은 고정 상수가 아니라 **관측 배치 규모에 대한 상대 기준**이어야 한다. 기준량은 **랜드마크 간 최대 이격(관측 스팬)** 이며 기기 이동 경로는 포함하지 않는다(걸을수록 관용이 커지는 역스케일링 방지). 초과 시 방향만 표시한다.

**관측 누적 — 정확도가 오르는 구조**

- **FR-107**: 동일 코드가 서로 다른 위치에서 관측되는 다중 표지판 환경에서, 시스템은 해당 코드를 제외하지 않고 **위치 클러스터(표지판 인스턴스)로 분리 수용**해야 한다. **표본 2개 이상인 클러스터만 채택**한다(단발 관측 유령 군집 배제).
  - **인스턴스 선택은 코드별 최근성이 아니라 조합의 기하 일관성으로 결정한다** — 후보 조합 중 격자 적합 잔차가 최소인 조합을 선택하고, 동률이면 현재 기기 위치에 가까운 조합을 택한다. 근거: 실측 주차장은 11.5m 간격의 평행 2열 구조여서 코드마다 독립적으로 최근 인스턴스를 고르면 서로 다른 열이 섞여도 잔차가 0으로 나오고(피치 12.95m 대 20.98m), 목표가 13.8m 어긋난 채 모든 게이트를 통과한다.
  - 선택된 조합이 바뀌면 그 자체가 불확실성 증가 신호이므로 백분율에 반영한다.
- **FR-108**: 오래된 관측은 제외 대신 **불확실성 팽창**으로 다뤄야 한다 — 시간 경과에 따라 해당 관측의 기여 가중치와 백분율을 낮추되, **목표 점추정 자체를 오염시키지 않는다**. 새로운 관측이 들어오면 회복된다.
- **FR-109**: 목표가 관측된 축 위에 있지 않아도(미지 축 오프셋 존재) 방향 추정은 수행되어야 하며, 그 오프셋은 불확실성으로 표현되어 FR-101·FR-103에 반영된다. 005 FR-009(b)의 "목표가 축 위에 있지 않으면 안내하지 않는다"는 규칙은 폐지한다.

**표현 — 화면**

- **FR-110**: 추가 관측이 필요한 상태에서 **그라디언트 힌트와 축 행동 지시가 함께** 전달되어야 한다. 한쪽이 다른 쪽을 대체·은폐해서는 안 된다.
- **FR-111**: 화면에는 **접이식 레이더 미니맵**이 있어야 한다. 접힘 상태도 정적 아이콘이 아니라 라이브 축소판으로, 사용자 위치(중심·진행 방향 위)·관측 기둥·목표 불확실성 영역(띠 또는 원)을 표시한다. 펼치면 같은 그림이 확대되며 코드 라벨·거리 눈금·이동 자취·축 방향이 추가된다. 기본 상태는 접힘이다.
- **FR-112**: 목표 근접 구간에서는 등록 시 저장된 기둥 **사진 카드**를 표시해 최종 확인을 돕는다. 사진이 없는 세션(수동 등록 등)에서는 목표 코드를 크게 보여주는 카드로 대체한다.
- **FR-113**: 화면의 동시 표시 부담을 제한해야 한다 — 큰 요소는 한 번에 하나(화살표), 코드 인식 피드백은 순간 표시(목록 누적 금지), 상태 문구는 상단 한 자리에서 교대 표시.

**등록 품질**

- **FR-114**: 스캔 등록 중 인접 기둥 확보를 **유도**해야 한다(권장 문구 + 확보 수 진행 표시). 저장을 지연하거나 차단하지 않는다(005 FR-002 유지).

**계측·검증**

- **FR-115**: 안내 표시 이벤트는 화살표 상태뿐 아니라 **모든 안내 상태**(힌트·근접·방향만 포함)에서 기록되어야 하며, 표시된 백분율과 문구를 포함해야 한다. **기존 로그·도구와의 호환은 신뢰도 필드만이 아니라 단계(stage) 필드까지 포함한다** — 연속량 모델로 바뀌어도 기존 stage 문자열에 대응하는 값을 계속 기록하고(또는 요약 도구가 신규 필드로 동등 지표를 계산할 수 있게 하고), 지표 스크립트가 구·신 로그를 모두 읽을 수 있어야 한다. 화살표 가동률(SC-101)의 산출 근거가 여기에 걸려 있다.
- **FR-116**: 신규 추정 규칙(클러스터·팽창·백분율·각도 보장)은 **리플레이어에도 동일하게 반영**되어야 한다(005 DR-003의 재현 계약 유지). 리플레이 결과는 기록된 값과 대조 가능해야 한다. **이 변경의 범위에는 기존 주차 테스트(격자 추정·리플레이 등 30여 건)와 현장 픽스처 7건의 기대값 재고정이 포함된다** — 재고정 결과는 "정직한 방향의 차이"임을 각 항목마다 확인한 뒤 확정한다.

### Key Entities

- **방향 추정(Direction Estimate)**: 목표 점추정 + **불확실성**(미지 축 방향의 길이, 관측 팽창 포함) + 신뢰 백분율. 기존의 단계(stage) 개념을 대체하는 연속량 중심 표현
- **표지판 인스턴스(Sign Instance)**: 같은 코드 문자열이 서로 다른 물리 위치에 존재할 때의 개별 랜드마크. 위치 클러스터와 관측 표본 수를 가진다
- **안내 표시(Guidance Presentation)**: 화살표(형태·각도·거리 표시 여부)·백분율·행동 지시·미니맵 상태·근접 카드로 구성되는 표시 묶음

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-101**: 260919 유형 세션(다중 표지판 + 16m대 구역 피치)의 리플레이에서 화살표 가동률이 0%에서 **60% 이상**으로 회복된다. **이 지표는 구조상 자명하게 상승하므로 단독으로는 통과 근거가 되지 못한다 — SC-102·SC-103·SC-104를 동시에 만족할 때만 통과로 판정한다**
- **SC-102**: 화살표가 표시된 모든 구간에서, 도착이 확인된 세션의 참값 기준 **방위 오차가 θmax 이내**다. **캘리브레이션과 검증은 서로 다른 세션으로 분리한다**(한 세션으로 θmax를 정하고 다른 세션으로 검증; 260801 D5·260911 H22를 역할을 바꿔 두 번 교차 평가). 같은 데이터로 정하고 같은 데이터로 확인하면 반증 불가능하므로 통과로 인정하지 않는다
- **SC-103**: 과거 과신 사고 구간(J21 102m 외삽·J22 30.3m 오차)에서 화살표가 **표시되지 않거나**(FR-101 보장 실패), 표시되더라도 백분율이 낮은 구간에 머물고 거리·실선이 나타나지 않는다. 특히 J21 후반(표시 거리 88~102m, 관측 스팬 40.6m)은 **미표시**가 기대 결과다 — 잔차가 0.1m로 작아도 적합 불확실성이 크므로 FR-101이 차단해야 한다
- **SC-104**: 목표 점추정의 자기 불안정성(한 스텝 최대 점프·누적 이동)이 현행 대비 악화되지 않는다
- **SC-105**: 사용자는 화살표 표시 여부와 무관하게 항상 **다음 행동**(무엇을 비추면 정확해지는지)을 안내받는다 — 안내 공백 구간 0
- **SC-106**: 되찾기 세션의 모든 안내 표시가 로그로 재현 가능하다(표시 백분율·문구 포함), 리플레이 결과와 기록의 불일치 0

## Assumptions

- 대상은 005와 동일(기둥 표지판이 있는 한국 대형 지하주차장). 표지판 간격은 실측 기준 축당 1.5~17m 범위를 포괄한다
- 각도 임계 θmax의 초기값은 30°이며, 도착 성공 세션의 참값으로 캘리브레이션한다(SC-102의 분리 원칙 준수)
- **격자의 등방성은 가정하지 않는다** — 실측에서 같은 주차장의 구역축 16.4m/스텝, 번호축 4.8m/스텝으로 3.4배 차이였다. 미지 축의 피치는 세션 내 추정값이 있으면 그 값을, 없으면 축별 사전 분포의 보수적 상한을 쓴다(FR-101)
- 미지 축의 **방향**은 관측된 축에 수직이라고 가정한다(직교 격자). 비직교 배치는 잔차·백분율로 드러나며 범위 밖이다
- 비 LiDAR 기기 검증(005 T046)은 본 기능과 별도 트랙으로 유지한다
