# PART 1. ⭐ 핀 기반 동네 인사이트 (별도 화면 킬러기능)

## 한 줄
> "지도에 핀을 톡 찍으면, **그 자리에 살면/가면 어떨지**를 서울 데이터로 한 화면에 보여준다."

## 왜 킬러인가
- 거대앱(네이버·카카오)은 "장소 검색 → 상호·리뷰"는 줘도, **"이 지점의 생활 환경을 종합"** 해 주진 않음 = 명확한 공백.
- 핀 기반이라 **경계 데이터·전 도시 전처리 불필요** → 가볍게 구현 가능(앞 논의 결론).
- "여기 살면 어때?" 핀 톡 = **공유·재방문 유발**(SNS성).

## 진입 & 화면 흐름
1. 지도 롱프레스 또는 검색 결과 → 핀 드롭
2. 하단 시트가 올라오며 **별도 인사이트 화면**으로 전개
3. 헤더: 행정동 주소 + **한 줄 요약**("조용하고 공기 좋은 주거 동네")

## 카드 구성 (서울 데이터 + 반경 질의)
| 카드 | 내용 | 데이터(서울) | 질의 방식 |
|---|---|---|---|
| 🏃 생활 활기 | 활발/보통/한적 + 시간대 미니그래프 | 생활인구(행정동) | 점→행정동 |
| 🌫 환경 | 대기질 등급, 소음 등급 | 실시간 대기환경, 소음 측정망/S-DoT | 점→구 / 측정소 보간 |
| 🚇 교통 | 최근접 지하철 도보 X분, 버스, 따릉이 | 지하철역·정류장·따릉이 좌표 | 반경/최근접 |
| 🏥 편의 | 반경 내 병원·약국·마트·편의점 수 | 약국·병원·대규모점포 | 반경 집계 |
| 🌳 녹지·산책 | 공원·둘레길 근접 | 도시공원·둘레길 | 반경/최근접 |
| 🌙 안전 | 야간 CCTV·보안등 밀도, 자치구 범죄수준, 침수이력 | CCTV·보안등·범죄통계·침수도 | 반경 / 점-폴리곤 |
| 🎉 지금 | 주변에서 열리는 행사 | 문화행사 | 반경 |

## 액션
- **두 지점 비교**(현재 동네 vs 이사 후보) ← 강력
- 관심 동네 저장/알림, 공유

## 수익 연계
- 부동산·이사·인테리어 **제휴**, "관심 동네 변화 알림" **구독**
- → 04에서 짚은 "무료+광고만으론 위험"의 보강 카드

## 표출 단계
- **1차(쉬움)**: 원시값 카드(점수화 X) — 경계·정규화 불필요
- **2차(고도화)**: 종합 점수(0~100) — 도시 분포 1회 전처리 필요

## 난도: 중하 (여러 서울 API를 점 기준으로 합성. 핵심은 Kakao 좌표→행정동 + 반경 질의)

# PART 2. ⏱ 시간여행 슬라이더 (별도 화면 킬러기능)

**한 줄**: 도시가 하루 동안 숨 쉬는 걸 슬라이더로 돌려본다. **시각 임팩트 최상 → 마케팅·바이럴 훅.**

**모델: 요일 × 시간 (요일별 패턴 기반)**
- 슬라이더 2축: **요일(월~일) × 시간(00~24)**. 요일 고르고 시간 끌면 그 요일의 전형적 하루가 지도에서 흐름.
- 모드: 인구 / 혼잡 / 대기질 / 연령필터(예: 20대만).
```
요일:  [월][화][수][목] ●금  [토][일]
시간:  00 ──────●19:00────── 24    ▶ 재생
```

**데이터 (서울만)**
| 레이어 | 데이터 | 성격 | 범위 |
|---|---|---|---|
| 기본 = "요일별 평소 패턴" | 생활인구(일자×시간×행정동×성별·연령) | 통계, **미리 계산해 앱 저장** | 전 지역 |
| 강화 = "오늘 vs 평소" | 실시간 도시데이터(citydata) | 라이브 | 주요 50~120곳 |

**기준선 정의**: 최근 **4~8주 요일 평균**을 기본(특이일 희석), "지난주 그 요일(전주)"은 옵션. 공휴일 제외.
→ "미래"도 별도 예측 API 없이 해결: "다음 금요일 저녁" ≈ "금요일들 저녁 패턴".

**덤 킬러 한 줄 — "오늘 vs 평소"**: 요일 평균(평소) 위에 오늘 실시간을 겹쳐 → *"지금 강남, 평소 금요일보다 20% 한산 👍"*. 어떤 앱에도 없음.

**구현 이점**: 요일×시간 패턴을 미리 계산·저장 → 슬라이더는 로컬 테이블만 읽어 **빠르고 실시간 API 호출 거의 없음**. citydata는 "오늘 vs 평소" 비교용으로만.

**페르소나**: 이사("이 동네 밤엔 조용한가") · 자영업자(손님 몰리는 시간대) · 나들이("그 공원 언제 한산") · 부모(놀이터 붐비는 시간) · 안전(인적 끊기는 시각, 06 밤길과 연결).

**한계**: 단위가 행정동(골목 정밀도 X) / 실시간 비교는 120곳 한정 / 시간별 히트맵 프레임 보간(crossfade) 렌더링이 핵심 작업(난도 중).

# PART 3. 🅿️ 지하주차장 내 차 찾기 (기둥코드 OCR 삼각측량 방식)

**한 줄**: 사전 실내지도·측위 인프라 **없이**, 주차장에 이미 붙은 **기둥 표지판(B2-A-3)을 랜드마크**로 써서 내 차 방향을 추정. (일반적 "실내 AR 내비"와 다른 자체 고안 방식 — **데이터 0**으로 개인 개발 가능, 거대앱도 안 함)

## 동작
1. **주차 시**: 내 위치 코드 저장(B2-A-3) + 개선안 — **인접 코드 2~3개·행/열 벡터·사진**까지 저장("차 주변 풍경")
2. **되찾을 때**: AR 카메라로 주변 기둥 촬영 → OCR로 코드들 읽기(B2-A-1, B2-A-2, B2-Z-10…)
3. 읽힌 코드의 **AR 3D 위치**로 번호 증가 방향(격자)을 추정 → 목표 코드 방향을 화살표로

## 기술 요소
| 요소 | 기술 | 가능성 |
|---|---|---|
| 표지판 OCR | Apple Vision `VNRecognizeTextRequest`(온디바이스) | ✅ 높음 (포맷 파싱이 난제) |
| 코드의 3D 위치 | ARKit raycast — 화면 속 텍스트 → 월드 메시 투영 → 3D 앵커 | ✅ 핵심 enabler |
| 번호 격자 추정 | {코드→3D위치}에 아핀 격자 피팅 `위치≈원점+i·행벡터+j·열벡터` → 목표 외삽 | 🟡 조건부 |
| 거리 단서 | 텍스트 크기(핀홀 근사) | 🟡 보조 |
| 드리프트 보정 | 코드 = semantic fiducial, 읽을 때마다 재앵커 | ✅ 강점(순수 VIO보다 강건) |

## 수학 (삼각측량)
B2-A-1@P1, B2-A-2@P2 → **열벡터 = P2−P1**. A행·B행 읽으면 직교 행벡터. 목표 ≈ `P(A-1) + 2·열벡터`. 코드 인덱스→공간 좌표 선형모델로 방향 산출.

## 핵심 가정·리스크
"번호가 선형 격자인가"가 유일·최대 리스크. 평면 격자+단조 증가면 잘 됨 / 곡선·나선·번호 리셋·구역 블록배치면 전역 외삽 부정확 → **가까울수록 정확**, 멀면 방향만 대강 후 근접 시 목표 기둥 읽어 확정(사람이 찾는 방식과 동일).

## 성격
절대 측위 ❌ → **점진적 방향 추정(warmer/colder + 화살표)**, 기둥 읽을수록 수렴.

## 개선안 (강건화)
주차 시 "코드 하나"가 아니라 **차 주변 이웃 격자(인접 코드+행/열 벡터+사진)** 저장 → 되찾을 때 현재 읽은 코드와 매칭 → 단일 라벨 외삽보다 훨씬 정확 + "도착 확인"까지.

## 한계
① 주차장마다 코드 체계 달라 **파싱 로직이 핵심 난제**(다회 읽기로 패턴 학습 완화) ② 선형 가정 붕괴 ③ OCR 오인식(가↔카, 0↔O, B↔8)·표지 가림·저조도 ④ ≥2개 코드 봐야 방향 생성(카메라 둘러봐야).

## 위치
도보 메인 정체성과는 별개 **부가 모듈**(운전자 대상). 데이터 0·차별성 강해 킬러 후보로 유효.

# PART 4. 기타 신규 킬러기능 후보 (페르소나별)

06에서 안 다룬 **새로운** 것 위주. 각 항목: 페르소나 / 컨셉 / 데이터 / 왜 킬러.

### A. 🏠 동네 비교 (2핀 나란히) — 이사 준비자
PART1의 확장. 두 동네를 카드 대 카드로 비교 + 통근 소요시간까지. 이사·직장이동의 결정 도구. **제휴 수익 강함.**

### C. 🤝 공정한 약속장소 — 모임·소개팅
여러 명 위치 입력 → 각자 **대중교통 등시간(等時間)** 인 공평한 지점 추천 + 그 주변 카페/한적·활기 분위기. 기존 "중간지점"은 단순 거리 중간 → 우리는 **시간 공정성 + 분위기.** 바이럴성. 데이터: 대중교통 + 생활인구 + 상권.

### D. 🚶‍♀️ 발견 산책 루프 — 산책러·관광객
"30분/1시간" 입력 → **한적+그늘+예쁜 공원** 경유하는 추천 산책 순환경로 생성(komoot식). 데이터: 공원·둘레길·생활인구·가로수. 도보 정체성의 꽃.

### E. 🌧 비 오는 날 모드 — 우천 보행자
비 예보 시 → **비 적게 맞는 길**(지하상가·지하철 연결·아케이드) + 침수 회피. 그늘길의 비 버전. 데이터: 지하상가/지하철 연결·침수도·날씨. 참신.

### F. 🛡 통학로 안전 점검 — 학부모
집→학교 경로의 **사고다발·횡단보도·어린이보호구역·CCTV** 점검 리포트. 공공·사회적 가치 + 학교/지자체 **제휴**. 데이터: 사고·CCTV·보안등·보도네트워크.

### G. 📍 "우리 동네 지금" 대시보드 — 동네 주민 (리텐션 엔진)
내 위치 기준 실시간 종합(대기질·혼잡·따릉이·날씨·행사)을 **홈 첫 화면/위젯**으로. "매일 열 이유" = 광고 노출의 토대. 데이터: 실시간 도시데이터 묶음.

### H. 🐶 반려 산책 지도 — 견주
반려동반 가능 공원·시설 + 그늘 + 한적 + 동물병원. 충성도 높은 틈새. 데이터: 공원·시설·생활인구.

## 권고 묶음 (제품 골격 가설)
- **홈** = "우리 동네 지금" 대시보드 (G) → 매일 열 이유
- **간판 킬러** = 핀 동네 인사이트(PART1) + 동네 비교(A) → 공유·제휴
- **도보 정체성** = 발견 산책 루프(D) + 06의 웰니스/안심 경로
- **시각 훅** = 시간여행 슬라이더(B) → 마케팅·바이럴

→ 이 4개가 "가볍고 깔끔 + 서울 데이터 큐레이션"이라는 차별화를 하나의 제품으로 묶음.
