# 4단계 MVP 범위 정의

작성일: 2026-06-19
결정(사용자): 주인공 = **도보(메인)**, 자전거는 보조(따릉이 레이어 + 도보기반 경로) / 포지셔닝 = **살아있는 데이터 지도 + 도보 특화 내비 (+ AR은 find-my-car 형태로 Later)** / 수익 = **무료+광고 유지**

---

## 제품 한 문장
> "거대 지도 앱이 무겁고 산만하게 묻어둔 것을, **도보 사용자를 위해 가볍고 깔끔하게** — 서울 실시간 데이터를 예쁘게 얹은 지도 + 도보 특화 길안내."

## 두 가지 원칙(못박음)
1. **가벼움이 제품의 정체성.** 광고는 절제된 형태만(전면광고·결과 도배 금지). 광고가 차별화를 죽이면 안 됨.
2. **AR은 데이터 없는 것부터.** find-my-car(주차위치 되찾기) = OK / 풀 실내 AR 내비 = 보류.

---

## 기능 분류 (Must / Should / Later / Drop)

### ✅ MUST — MVP 출시 필수
| 기능 | 상태 | 비고 |
|---|---|---|
| 가볍고 깔끔한 홈/지도 UI | 진행 중(002-ui-design-refresh) | 정체성 핵심, 먼저 완성 |
| 도보 길안내 (turn-by-turn) | 엔진 있음 | **메인 기능.** 도보 모드 다듬기 |
| 따릉이 실시간 레이어 | 구현됨 | 자전거 보조 자산 (대여소 위치/잔여) |
| (보조) 자전거 = 도보경로 기반 | 부분 | 도보 경로 + 계단 회피 + 자전거 ETA. 풀 자전거 라우팅은 Later |
| 데이터 레이어 1~2개 | 신규 | 미세먼지(대기질 단계구분도) + 공중화장실 마커 (도보 실수요) |
| 검색 / 즐겨찾기 | 있음 | 유지 |
| 절제된 광고 슬롯 | 신규 | 무료+광고, 비침습적 |

### 🟡 SHOULD — MVP 직후
- 도보 야간 안심경로 (안심귀갓길 + 보안등/CCTV)
- 시간대별 인구밀도 히트맵 ("한적한 길")
- 오늘 주변 문화행사 마커
- 공원·둘레길 코스(점+선)
- 실시간 도로 소통 레이어(자전거 차도 주행 시)

### 🔵 LATER — 후속 모듈
- **AR 주차위치 되찾기(find-my-car)** — ARKit만, 데이터 불필요
- 옥외 도보 AR(Live View형) — 고난도, 장기 R&D
- 대중교통(버스·지하철) 심화 — 보조 레이어로만(주인공 아님)
- CarPlay 재통합 / 계정·클라우드 동기화
- 모빌리티·지역상권 제휴 수익(광고 보강)

### ❌ DROP / 보류
- **지하주차장 풀 실내 AR 내비** — 공공데이터 토대 없음(자체 측량 필요, 범위 밖)
- **차량 내비 차별화 시도** — 제공 API 한계, 보조 기능으로만 유지
- 3D 차량 아이콘 — 우선순위 낮음

---

## MVP 최대 리스크
1. **무료+광고 수익성** — 시장규모·손익 MAU 미확보(02 미해결). 광고만으로 지속 가능한지 별도 보강 조사 권고.
2. **차별화 깊이** — 도보 길안내 자체는 네이버·카카오도 함. **"가벼움 + 도보 특화 데이터 큐레이션"** 으로 이겨야 함. 데이터 레이어 완성도가 핵심.
3. **스코프 규율** — "데이터 폭"이 넓어 MVP가 비대해질 위험. MUST를 위 표로 고정.

(해소됨: 자전거 전용 라우팅 데이터 리스크 → 자전거를 도보경로 기반 보조로 강등하며 제거. 계단 회피만 확인하면 됨.)
