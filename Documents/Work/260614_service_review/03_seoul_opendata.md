# 서울시 공공데이터 활용 검토 — 다각도 발굴

작성일: 2026-06-19
목적: "지도에 시각적으로 얹기 좋은" 서울 공공데이터를 카테고리 무관하게 발굴하고, 진행할 만한 기능 후보 도출
방법: 4개 카테고리(실시간·모빌리티 / 도시·환경 / 시설·POI / 안전·실내공간) 병렬 조사, 각 데이터셋 출처 URL 검증

---

## 핵심 결론 먼저

1. **"실시간 데이터 레이어를 가볍고 예쁘게 보여주는 지도"는 데이터 토대가 매우 풍부하다.** 서울은 실시간 소통(선)·혼잡도(면, AI예측 포함)·대기질(단계구분도)·따릉이(점)가 모두 OpenAPI로 열려 있다. 대기업 앱은 이걸 무겁고 산만하게 보여주는데, **가볍고 깔끔하게 토글하는 앱**은 포지셔닝("가벼움 + 서울 공공데이터 심화")과 정확히 맞는다.

2. **❌ 지하주차장 AR 내비의 공공데이터 토대는 "불가"다.** 층별 실내도면도, 실내측위 인프라도 공공데이터에 없다. 시장 참여자(현대오토에버·카카오모빌리티·강남구)도 공공데이터가 아닌 자체 LiDAR/SLAM 측량 + 건설사 CAD로 직접 구축한다. → 이 기능은 **개인/소규모로는 데이터 확보가 사실상 불가능**. 비전에서 빼거나 장기 보류 권고.

3. **⚠️ 자전거 "전용 경로" 데이터가 약하다.** 따릉이 대여소 실시간은 최상급이지만, 서울 자전거도로 GIS는 서비스 중단·안내지도는 PDF뿐. 자전거 전문 라우팅을 하려면 자체 데이터/OSM 보강 필요.

## 진행할 만한 기능 후보 (우선순위)

### Tier 1 — 즉시·고임팩트·구현 쉬움
| 기능 | 데이터 | 표현 | 비고 |
|---|---|---|---|
| 실시간 도로 소통 색상 오버레이 | TOPIS 실시간 소통정보 | 선(원활/서행/정체) | 내비 앱의 "라이브" 체감 1순위, 경로 혼잡 회피 직결 |
| "지금 붐비는 곳" 혼잡도 + AI 예측 | 실시간 도시데이터 citydata | 면/점 (50~120곳) | **미래 12시간 예측** → 도착시점 혼잡도, 차별화 큼 |
| 실시간 미세먼지 단계구분도 | 자치구별 실시간 대기환경 `RealtimeCityAir` | 단계구분도(25구) | 매시 갱신, 시민 관심↑, 구현 쉬움 |
| 따릉이 실시간 잔여 | 따릉이 `bikeList` (OA-15493) | 점 + 잔여수 | **이미 구현됨**, 라이브 체감 확실 |
| 가까운 화장실 | 공중화장실 위치(15146086) | 점 | 도보 실수요 1위, CSV 내장→오프라인 가능 |
| 무료 공공와이파이 | 공공와이파이(OA-20883) | 점 | 매주 갱신, 좌표 확실 |

### Tier 2 — 좋은 콘텐츠
| 기능 | 데이터 | 표현 |
|---|---|---|
| 시간대별 인구밀도 히트맵 ("한적한 길") | 생활인구 집계구/행정동 | 단계구분도(애니메이션) |

### Tier 3 — 보조/틈새
- 응급실 실시간 가용병상 + AED (긴급 한정, 일반 지도라면 1순위급)
- 상권 추정매출 / 아파트 실거래가 (단계구분도, niche)
- 공영주차장 실시간 잔여(5분, 503개소) — AR 없이 "주차 찾기·잔여"는 가능
- 도서관·박물관·미술관 등 문화시설 마커

## 데이터로 인해 재고가 필요한 비전 항목
- **지하주차장 AR 내비** → 공공데이터 토대 없음. 자체 측량 필요 = 개인 범위 밖. **보류 권고.**
- **도보 AR** → 실내와 다름. ARKit + 시각측위(VPS)는 옥외에서 기술적으로 가능하나, 이는 공공데이터가 아닌 별도 기술 트랙(시장조사 워크플로에서 별도 검토 중).
- **자전거 전문 내비** → 따릉이는 강하나 자전거 전용도로 라우팅 데이터 약함. OSM 등 보강 전제.

## 여기서 떠오르는 대안 포지셔닝 (가설 B)
> **"서울을 가장 예쁘게 보여주는 살아있는 지도."**
> 거대 앱이 무겁고 산만하게 묻어둔 실시간 데이터(소통·혼잡·대기질·따릉이·행사)를, **가볍게 토글하는 깔끔한 레이어 UI**로 제공. AR이라는 고위험 기술 대신, **이미 열려 있는 풍부한 공공데이터 + 디자인 감각**으로 차별화.

→ 1단계의 가설 A(이동수단 특화 + AR)와 비교해 **데이터 리스크가 훨씬 낮음.** 3단계 포지셔닝 결정에서 A vs B를 비교 검토할 것.
