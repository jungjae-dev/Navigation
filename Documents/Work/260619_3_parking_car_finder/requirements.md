# 요구사항 — 지하주차장 내 차 찾기 (기둥코드 OCR 격자 추정)

출처: Documents/Work/260614_service_review/07_killer_features.md (PART 3)
방식: 사전 실내지도·측위 인프라 **불필요**(데이터 0). 주차장에 이미 붙은 기둥 표지판(B2-A-3)을 랜드마크로 사용.
대상 단계: speckit-specify 입력 브리프. 도보 메인과 별개 **부가 모듈**(운전자 대상).
개정: 2026-07-10 v2 — 타당성 검토 반영(격자 피팅 최소 관측 수 정정, 강등 상태 기계 추가, 오검출 필터·세션 수명주기·디버그 요구사항 신설).

---

## 1. 개요 / 목적
주차 시 내 위치 코드를 저장하고, 되찾을 때 AR 카메라로 주변 기둥 코드들을 OCR로 읽어 **번호 증가 방향(격자)을 추정**해 내 차 방향을 가리킨다.
- 성격: **절대 측위 아님** → "점진적 방향 추정(warmer/colder + 화살표)". 기둥을 읽을수록 추정이 수렴.
- 강점: 코드 = semantic fiducial → 읽을 때마다 재앵커되어 순수 VIO 드리프트보다 강건.
- **정체성: "정확한 안내"가 아니라 "정직한 안내"** — 추정이 불확실하거나 모델이 깨지면 그 사실을 감지하고 정직하게 강등한다. 강등 경로가 기능의 절반이다.

## 2. 목표 / 비목표
- 목표: 데이터 없이 내 차 방향 안내(되찾기). 코드 OCR + ARKit 3D 앵커 + 단계적 격자 외삽 + 모순 감지·강등.
- 비목표: 빈자리 안내(T2), 턴바이턴 실내 경로, 멀티층 자동 경로, 절대 좌표, **다중 차량 동시 관리**.

## 3. 사용자 시나리오
1. 주차 직후: 가까운 기둥 코드(B2-A-3)를 수동 입력 또는 **AR 촬영 자동 인식** + 사진 저장. 코드에 층 표기가 없으면 층을 별도 확인 입력.
2. (선택) 주변 인접 코드 2~3개도 함께 인식해 "차 주변 풍경" 저장(인접 관계로 저장).
3. 쇼핑 후 복귀: 같은 층(B2) 도달 → AR 카메라로 주변 기둥 촬영.
4. 앱이 읽힌 코드들로 격자 추정 → 내 차 방향 화살표 + 거리감 + 신뢰도 표시. 관측이 부족하면 **무엇을 더 비춰야 하는지**(다른 구역/다른 번호) 특정해서 안내.
5. 번호 배치가 불규칙한 주차장(스네이크 등)이면 모순을 감지하고 근접확인 모드로 강등 — "근처 도착, 주변 기둥에서 B2-A-3을 직접 확인하세요".
6. 목표 코드(B2-A-3) 직접 인식 시 "도착".

## 4. 기능 요구사항 (FR)
- **FR-1 주차 등록**: 수동 코드 입력 + AR 촬영 자동 인식(인식 결과 확인·수정 가능). 인접 코드/사진/시각 저장(SwiftData). **코드에 층 토큰이 없으면 층을 별도 필드로 확인 입력받는다**(층 표기가 기둥에 없는 주차장 대응).
- **FR-2 코드 OCR**: **AR 세션 프레임(`ARFrame.capturedImage`)** 을 Apple Vision `VNRecognizeTextRequest`(온디바이스)로 OCR → 기둥코드 텍스트 검출(프레임 throttle). (방식 확정 — 표준 파이프라인)
- **FR-3 코드 파싱 + 오검출 필터**: 코드 문자열 토큰화 → (층 / 구역 / 번호) 구조 추론. 일반 패턴 우선 지원(영문구역-숫자, 한글구역(가/나/다)-숫자, 층 접두 B/지하). **되찾기 시에는 등록 코드의 포맷을 템플릿으로 삼아 같은 포맷의 텍스트만 후보로 인정한다** — 차량 번호판(12가3456), 안내문 등 오검출이 격자에 유입되는 것을 차단(파서 난제도 "범용 파싱"에서 "템플릿 매칭"으로 축소).
- **FR-4 AR 3D 앵커**: 인식된 텍스트의 화면 좌표 → ARKit raycast → world anchor. {코드 → 3D position} 누적. **앵커 실패 처리**: raycast 실패로 위치를 못 얻은 코드도 층 확인·도착 확정에는 사용한다(격자 피팅에만 미포함). 실패가 반복되면 "기둥에 더 가까이 / 손전등을 켜보세요" 안내. ARKit 트래킹 품질 저하(limited) 시 "천천히 움직여주세요" 등 상태 안내.
- **FR-5 단계적 격자 추정**: 관측 수·구성에 따라 단계적으로 동작한다(완전한 2D 아핀 피팅의 미지수는 6개 → 비공선 관측 **3개 이상** 필요).
  - 유효 코드 **1개**: 방향 추정 불가 → "주변 기둥을 더 비춰주세요".
  - **2개, 단일 축 차이**(같은 구역·번호 상이, 또는 같은 번호·구역 상이): 해당 축의 **1D 외삽** — 목표가 그 축 위에 있을 때만 방향 안내.
  - **2개, 혼합 축 차이**(구역·번호 모두 상이): 변위가 두 축의 합성이라 분해 불가 → **부족한 축을 특정해** 추가 관측 안내("다른 번호의 기둥을 하나 더 비춰주세요").
  - **3개 이상 비공선**: **2D 아핀 격자**(행벡터·열벡터) 최소제곱 피팅 → 목표 코드 위치 외삽. `위치 ≈ 원점 + i·행벡터 + j·열벡터`.
- **FR-6 방향 안내**: 목표 방향 AR 화살표 오버레이 + warmer/colder + **추정 신뢰도** 표시. 현재 추정 단계(관측 부족 / 1D 축 / 2D 격자 / 강등)가 사용자 표현에 구분되어 드러나야 한다.
- **FR-7 모델 모순 감지·강등 (상태 기계)**: 코드를 새로 읽거나 재관측할 때마다 "모델 예측 위치 vs 실제 관측 위치"의 **잔차**를 평가한다. 잔차가 임계를 초과하면(스네이크 번호 배치, 구역 블록 배치, 번호 리셋 등 격자 가정 붕괴): 신뢰도 강등 → 화살표 숨김 → **근접확인 모드** 전환("이 주차장은 번호 배치가 불규칙합니다. 주변 기둥에서 목표 코드를 직접 확인하세요"). 이후 정합 관측이 누적되면 안내 모드로 복귀 가능.
- **FR-8 근접 확정**: 목표 코드 자체 인식 시 "도착" 확정. 단 **일시적 OCR 오인식(8↔3, 0↔O 등) 한 번으로 확정되지 않아야 한다** — 연속 인식 등 확정 조건 필요(임계값은 plan에서 정의).
- **FR-9 드리프트 보정**: 코드 재인식 시 앵커 재정렬(loop-closure 유사).
- **FR-10 폴백**: AR/격자 실패 시 저장한 **사진 + 코드 텍스트** 표시(수동 찾기 지원). **카메라 권한 거부 시에도 수동 입력 등록 + 저장 정보 열람은 완전히 동작**해야 하며, 카메라 기능 진입 시 설정 이동 안내.
- **FR-11 세션 수명주기**: 활성 주차 기록은 **동시에 1개**. 이미 활성 기록이 있는 상태에서 새로 등록하면 안내 후 대체. 도착 확정 또는 수동 "찾았어요"로 완료 처리. 완료된 기록(사진 포함)은 최근 1건만 보관하고 이전 기록은 삭제.
- **FR-12 강건화(Later)**: 주차 시 저장한 인접 관계와 현재 읽은 코드 매칭 → 단일 라벨 외삽보다 정확 + 도착 확인.

## 5. 개발 지원 요구사항 (DR) — 디버그 빌드 한정
현장(실제 지하주차장)에서만 재현되는 기능 특성상, 파이프라인 각 단계의 상태를 현장에서 즉시 확인하고 사후 분석할 수단이 필요하다. constitution 원칙 IV(로그 기반 검증)의 확장.
- **DR-1 AR 디버그 시각화**: 공간 오류는 공간에 그려야 보인다.
  - 코드 앵커 라벨(인식 코드 + 신뢰도 색상) — raycast 오배치 즉시 식별
  - 추정 격자 축 화살표 + 외삽 고스트 격자점(예측 인덱스 라벨) — 모델 vs 실제 배열 비교
  - 목표 예측 위치 고스트 마커
  - 잔차 선(예측 위치 → 실제 관측 위치) — 강등 트리거 시점 시각 확인
  - raycast 히트/실패 표시, 이동 궤적
  - ARKit 내장 debugOptions(특징점 구름 등) 토글 — 트래킹 문제 vs 알고리즘 문제 현장 구분
- **DR-2 상태 텍스트 스트립**: 비공간 정보는 화면 상단 한 줄 — 상태기계 단계(관측부족/1D/2D/강등), OCR 기각 사유, 관측 수, 신뢰도 수치.
- **DR-3 관측 레코딩·리플레이**: 세션 이벤트(인식 코드, 앵커 위치, 트래킹 상태, 타임스탬프)를 NDJSON으로 기록(기존 `LocationRecorder` 패턴 준용). 격자 피팅·파싱은 순수 계산이므로 현장 기록을 책상에서 리플레이하며 수정 + 유닛 테스트 자산화. 스파이크(코드 포맷 수집)의 수집 도구 겸용.
- **DR-4 로그 포인트**: 상태 전이, 강등 발생, OCR 기각 사유를 Logger로 기록 — Phase 검증 기준과 연결.

## 6. 기술 구현 노트
- AR: `ARWorldTrackingConfiguration`. 화살표 렌더 RealityKit 또는 SceneKit.
- OCR: Vision 프레임 처리(성능 위해 N프레임당 1회, 관심영역 제한).
- 수학: 아핀 피팅(최소제곱), 인덱스→공간 선형모델. 비공선 판정, 잔차 기반 모순 감지, 이상치 제거(RANSAC 유사).
- 저장: SwiftData(주차 세션: 코드, 층, **인접 코드 관계(인덱스)**, 사진 경로, 시각, 상태). ⚠️ AR 월드 좌표·격자 벡터는 세션마다 좌표계가 새로 생성되므로 **세션 간 재사용 불가 — 저장 금지**. 세션을 넘어 유효한 것은 코드 간 인접 관계뿐.
- 권한: 카메라(NSCameraUsageDescription). 사진은 로컬 저장만.
- 패턴: 기존 MVVM + Combine. AR 세션 상태 `CurrentValueSubject`.

## 7. 비기능 요구사항
- 성능: OCR 프레임률 제한으로 발열·배터리 관리.
- 저조도: 노출/대비 보정, 필요 시 손전등 토글.
- 프라이버시: 카메라 영상 비저장(코드/사진만 사용자 로컬).
- 정확도 표현: 불확실성을 신뢰도/"대략 이 방향"으로 정직하게 표시(과신 금지).
- **기기 계층**: LiDAR 탑재 기종(iPhone Pro 계열)은 풀 경험 기준. 비 LiDAR 기종은 raycast 품질 저하를 전제로 **강등 경로(층 확인 + 코드 목록 + 사진 폴백) 중심으로 성립**하면 정상 범위. 성공 기준을 기기 무관 단일 수치로 잡지 않는다.

## 8. 핵심 가정 / 리스크
- **선형 격자 가정**: 번호가 평면 격자+단조 증가일 때 정확. 곡선·나선·번호 리셋·스네이크(통로마다 역방향)·구역 블록배치면 전역 외삽 부정확 → **FR-7 모순 감지로 강등**하고 근접 확정에 의존. "가까울수록 정확, 멀면 방향만 대강"이 정상 동작.
- **코드 포맷 다양성**: 주차장마다 체계가 다름 → 등록 코드 템플릿 매칭(FR-3)으로 문제 축소 + 스파이크로 실태 수집.
- OCR 오인식(가↔카, 0↔O, B↔8), 차·기둥 가림, 저조도.
- 방향 생성에 코드 2개(단일 축) 또는 3개+(2D) 필요 → 사용자가 카메라를 둘러봐야 함. 부족한 축을 특정해 안내(FR-5)로 완화.

## 9. 엣지 케이스
- 코드 1개만 보임 → "주변을 더 비춰주세요" 안내(방향 불가).
- 코드 2개가 혼합 축(구역·번호 모두 상이) → 분해 불가, 부족한 축 특정 안내.
- 한 구역 코드만 계속 읽는 경우 → 다른 구역 방향 미지 → "다른 구역 기둥을 비춰주세요".
- 코드 체계 인식 실패 → 수동 입력 + 사진 폴백.
- **번호판·안내문 오검출** → 등록 코드 포맷 템플릿 불일치로 기각(FR-3).
- **raycast 실패**(코드는 읽힘, 위치 없음) → 층 확인·도착 확정에만 사용 + 근접/손전등 안내(FR-4).
- 앱 종료/세션 손실 → 저장한 코드·사진으로 재시작.
- 다른 층 → 층 코드 불일치 경고("B2로 이동하세요"). **층 토큰이 코드에 없는 주차장** → 등록 시 별도 입력받은 층으로 상기("B2에 주차하셨습니다").
- 동일 코드 중복(다른 층 같은 번호) → 층 토큰(또는 별도 입력 층)으로 구분.
- **카메라 권한 거부** → 수동 등록 + 열람은 정상 동작, 카메라 기능은 설정 안내.

## 10. MVP 범위
- MVP: 주차 등록 + 사진 + 폴백(FR-1,2,10) + 되찾기 단계적 격자 안내(FR-3~6) + 모순 감지·강등(FR-7) + 근접 확정(FR-8) + 세션 수명주기(FR-11) + 디버그 지원(DR-1~4).
- Later: 인접 관계 매칭 강건화(FR-12), 드리프트 정밀 보정 고도화, 빈자리 안내(T2), 멀티층.

## 11. 확인 필요 (스파이크)
- ✅ **OCR 방식 확정**: `ARFrame.capturedImage` → Vision `VNRecognizeTextRequest`로 기둥코드 인식 가능(표준 파이프라인).

## 12. 현 앱 통합 (Integration)
현 구조: 탭바 없음 → `HomeViewController(루트)` + 내장 `MapViewController` + `DrawerContainerManager`. **이 기능은 지도/드로어와 무관한 독립 풀스크린 모듈**(지하라 GPS 없음 → 지도 마커 무의미).

### 진입 (홈 드로어 버튼)
- `Feature/Home/HomeDrawerViewController`에 **별도 버튼**("내 차 찾기" / 주차 아이콘) 추가 → 콜백 → `AppCoordinator.showParkingFinder()`.

### 표시 (풀스크린 present)
- AR 카메라 화면은 드로어 패턴이 안 맞음 → **풀스크린 present** (`modalPresentationStyle = .fullScreen`, 검색 화면이 present되는 방식과 유사하나 풀스크린).
- 한 화면 안에서 2개 흐름 전환: **(a) 주차 등록**(코드/사진 저장) ↔ **(b) 차 찾기**(AR 격자 추정). 상단 토글 또는 진입 시 분기.
- 종료: 닫기 버튼 → dismiss → 홈 복귀.

### 지도와의 관계
