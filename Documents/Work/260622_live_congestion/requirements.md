# 요구사항 — 실시간 도시 혼잡 지도 (Live City Pulse)

출처/피벗: 260619_2_timetravel_slider(과거 평균 컨셉)에서 전환. 과거 생활인구 평균은 **수동 전처리 필요**라 폐기 → **서울 실시간 도시데이터(citydata)의 실시간 혼잡 + 향후 12h 예측**을 그대로 쓰는 라이브 컨셉으로 교체.
제품 방향: 도보 메인 + 살아있는 데이터 지도. 서울 공공데이터만. **전처리·임베딩 데이터 없음(라이브)**.
대상 단계: speckit-specify 입력 브리프.

---

## 1. 개요 / 목적
지도에 서울 주요 장소(~120곳)의 **실시간 혼잡도**를 색으로 띄우고, 슬라이더로 **지금 → 향후 12시간 예측**을 돌려본다. "지금 어디가 붐비나, 1시간 뒤엔?" 을 라이브로 답한다.
- 데이터는 **실시간 API**(citydata)가 혼잡도 단계와 12h 예측을 직접 제공 → **미리 계산·수동 전처리 없음**.
- 슬라이더 UX는 시간여행과 동일하되, 축이 "과거 요일×시간"이 아니라 "**지금 +0h ~ +12h**".
- 도보 메인과 정합: "지금 갈까 말까 / 한산해지는 시간".

## 2. 목표 / 비목표
- 목표: 주요 장소의 실시간 혼잡 + 단기 예측을 지도에서 한눈에. 슬라이더로 가까운 미래 스크럽.
- 비목표(MVP): 전 지역(424 행정동) 커버(citydata는 ~120곳만), 과거 평균/요일 패턴, 운전자向 도로·주차, 미래 12h 초과 예측.

## 3. 사용자 시나리오
- (나들이) "지금 성수동 붐비나? 2시간 뒤엔 좀 빠지나?"
- (약속) "강남역 지금 사람 많아? 7시에 만나는데 그땐?"
- (산책) "한강공원 지금 한산한 곳은?"
- (회피) "붐비는 데 피해서 걷고 싶다."

## 4. 기능 요구사항 (FR)
- **FR-0 진입**: 홈 `MapControlButtonsView`에 **전용 플로팅 버튼**(맥박/혼잡 아이콘) → 탭 시 실시간 혼잡 모드 진입(혼잡 레이어 ON + 시간 드로어).
- **FR-1 실시간 혼잡 레이어**: 주요 장소(~120) 위치에 **혼잡 단계별 색 마커/영역**(붐빔/약간붐빔/보통/여유) 표시. 진입 시 현재(+0h) 기준.
- **FR-2 시간 슬라이더(지금→+12h)**: 하단 드로어에 0~12시간 스크럽 + (선택) 재생. 이동 시 각 장소 색을 그 시각 **예측값**으로 갱신.
- **FR-3 장소 상세**: 마커 탭 → 그 장소의 실시간 인구/혼잡 + 12h 예측 곡선 + (있으면) 보조정보. 1번 핀 인사이트 팝업 패턴 재사용 가능.
- **FR-4 데이터 신선도**: 실시간값은 짧은 TTL 캐시(예: 5~10분), 진입/갱신 시 표시 시각(예: "기준 14:30") 노출.
- **FR-5 자동 새로고침/수동 새로고침**: 모드 유지 중 주기 갱신 또는 사용자 새로고침.
- **FR-6 종료/복원**: 모드 종료 시 레이어 clear + 진입 전 레이어 상태·홈 드로어·지도 영역 복원.
- **FR-7 결측/범위 밖**: citydata 미포함 지역·일시적 응답 실패 → 해당 장소 숨김 또는 중립 표시(데이터 없음 안내).
- **FR-8 가독성/접근성**: 혼잡 단계 색은 색각·명도 고려, `Theme.Palette` 경유. 위성 위 가독성 위해 표준 지도 고정.

## 5. 데이터 소스
| 레이어 | 데이터셋 | 성격 | 범위 |
|---|---|---|---|
| 실시간 혼잡 + 예측 | **서울 실시간 도시데이터 citydata**(또는 경량 `citydata_ppltn`) — `AREA_CONGEST_LVL`(혼잡단계), `LIVE_PPLTN`(실시간 인구), `FCST_PPLTN`(시간별 예측, ~12개) | **라이브** | 주요 ~120 장소(POI) |
| (보조) 대기질 | RealtimeCityAir OA-1200 | 라이브 | 자치구 |

**검증 메모(확인 필요)**:
- citydata는 **장소(POI)별 호출** 구조로 보임 → 전체(~120) 표시 시 **호출량/병렬·캐시 전략** 필요(보이는 영역만 로드 등).
- `FCST_PPLTN` 예측 시간 범위/간격(시간 단위, 개수) 실데이터 1회 확인.
- POI 좌표/경계: citydata 응답에 좌표 포함 여부 — 없으면 장소명→좌표 매핑 테이블(소량, 번들).
- 과거 시계열은 사용 안 함(라이브+예측만).

## 6. 현 앱 통합 (Integration) — 시간여행 설계 재사용
현 구조: `HomeViewController(루트)` + 내장 `MapViewController` + `DrawerContainerManager`. 실시간 혼잡은 **라이브 레이어 + 시간 드로어** 한 쌍의 "모드".
- 진입: `MapControlButtonsView` 전용 버튼 → `AppCoordinator.showLivePulse()`.
- 활성: `MapViewController.setCongestion(...)`(마커/영역 오버레이) + `drawerManager.pushDrawer(LiveDrawerVC, 낮은 높이)`.
- 진입 시 기존 홈 요소: 홈 드로어 내려감 / 따릉이·버스 레이어 **자동 OFF(배타)** / 위성→표준 고정 / 카메라 현재영역 유지.
- 종료: `popDrawer` → `clearCongestion` → 진입 전 상태 복원.
- 신규: `Feature/LivePulse/`(LiveDrawerVC, LivePulseViewModel[`CurrentValueSubject<(offsetHour, ...)>`]), `Service/LivePulse/`(CitydataService, TTL 캐시), 혼잡 마커/오버레이. 재사용: 드로어 push/pop, 레이어 토글 패턴, 핀 인사이트 상세 팝업, `Theme`.

## 7. 기술 노트
- 패턴: MVVM + Combine, `CurrentValueSubject`로 (offsetHour, refreshState) 상태.
- 데이터: **실시간 호출 + 단기 TTL 캐시**(전처리/임베딩 없음). 호출량 관리(보이는 영역·상위 N·병렬+타임아웃). 서울 API 불안정 이력 → 타임아웃·부분실패 허용·중립 표시.
- 슬라이더: offset 0~12 → 각 장소 `FCST_PPLTN[offset]` 색. 현재(+0)는 `AREA_CONGEST_LVL`.
- 렌더링: 장소 마커(혼잡색) 우선(MVP). 영역 색칠은 좌표/경계 확보 시 후속.

## 8. 비기능
- 실시간성: 표시 기준 시각 명시, 합리적 TTL.
- 회복력: 부분 실패시에도 받은 장소만 표시, 빈 곳 중립.
- 접근성: 혼잡 색 색각/명도, Theme 토큰.
- 오프라인: 라이브 특성상 네트워크 필요(캐시 있으면 마지막값 표시 + 기준시각 노출).

## 9. 엣지 케이스
- API 일부/전체 실패 → 받은 것만, 또는 "데이터 없음" 안내.
- 예측 필드 결측/짧음 → 가능한 offset까지만 슬라이더 활성.
- citydata 미포함 장소 → 표시 안 함.
- 모드 중 네트워크 끊김 → 마지막 캐시 + 기준시각, 새로고침 유도.

## 10. MVP 범위
- MVP: 실시간 혼잡 마커 레이어(FR-0,1) + 지금→+12h 슬라이더(FR-2) + 장소 상세 예측 곡선(FR-3) + 신선도/복원(FR-4,6,7).
- Later: 영역 색칠(좌표/경계 확보 시), 자동재생/속도, 대기질·따릉이 흐름 결합, 도보 경로와 "혼잡 회피" 연계, 핀 인사이트 시간곡선 통합.

## 11. 주의
- citydata **호출량·안정성**이 최대 리스크 → 캐시·부분실패·보이는영역 로드로 방어.
- 커버리지 ~120곳 한계를 UX로 정직하게(빈 지역은 "데이터 없음").
