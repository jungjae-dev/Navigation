# 작업 템플릿 & 대시보드 시스템 — 요구사항

## 목적

Claude Code(VSCode Extension) 기반 작업 시, 워크플로우 상태를 자동으로 관리하고 대시보드 GUI를 통해 한눈에 파악하고 제어할 수 있는 시스템 구축.

---

## 배경

### 현재 작업 방식
새 작업 시작 시 폴더를 만들고 아래 순서로 진행:
1. 요구사항 문서 (`requirements.md`)
2. 플랜 문서 (`plan.md`)
3. 실행 문서 (`implementation.md`) — 단계별 실행 + 검증 항목
4. 브랜치 생성 → 단계별 커밋
5. 완료 문서 (`completion.md`) → MR

### 문제
- 대화가 길어지면 현재 단계/작업 내용 파악이 어려움
- 대화 간(세션 전환) 컨텍스트 복원 불명확
- 현재 어떤 문서를 봐야 하는지, 무엇이 완료됐는지 한눈에 보이지 않음

---

## 요구사항

### 1. 작업 시작
- 특정 방식(커맨드 또는 트리거)으로 작업을 시작하면 워크플로우가 초기화됨
- 표준 폴더/파일 구조 자동 생성
- 폴더명 규칙: `YYMMDD_{작업명}/`
- 대시보드 자동 오픈

### 2. 자동 상태 관리
- 워크플로우 단계(requirements → plan → implementation → completion)에 따라 상태가 자동으로 관리됨
- Claude가 작업 진행에 따라 상태를 업데이트
- 단계 전환 시 상태 파일 갱신
- 대화가 바뀌어도(세션 재시작) 상태 파일을 읽어 현재 단계 복원

### 3. 상태 기반 작업
- Claude는 현재 상태를 인지하고, 해당 단계에 맞는 작업을 수행
- 예: requirements 단계 → 요구사항 정제 집중 / plan 단계 → 코드 검토 및 설계

### 4. 대시보드 GUI
- **한눈에**: 현재 단계, 작업명, 각 문서 상태, 최근 활동을 한 화면에서 파악
- **문서 접근**: GUI에서 각 문서(requirements.md, plan.md 등)를 직접 열기 가능
- **문서 업데이트**: 중간에 요구사항/플랜 변경 시 GUI에서 문서에 접근해 수정 가능
- **상태 제어**: GUI에서 단계 전환 등 액션 처리 가능 (단순 뷰어가 아닌 컨트롤 패널)
- 상태 파일 변경 시 자동 갱신

### 5. 적용 범위
- 미결: 글로벌(모든 프로젝트) vs Navigation 프로젝트 전용
