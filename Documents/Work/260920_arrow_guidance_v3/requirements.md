## 1. 배경 (조사 결과 요약)

화살표는 세 번의 수정으로 단계적으로 조여졌다. 각각 실제 사고가 동기였고 개별로는 타당했으나, 누적 효과가 과잉 억제에 도달했다.

| 260814 반영 | 046902b | 도착 순간 목표 10.2m 오차(260801) | 신선도 30s 컷 — 걸을수록 유효 관측 감소 |

260919 0%의 직접 원인: 동일 코드 다중 표지판 제외가 '3'행 코드(F3·G3·H3·J3)를 전멸시켜 목표 J5의 번호 축이 성립 불가 + 형성된 추정도 레버 4.77(>2.5)로 차단. 부가 결함: needMore의 축 행동 지시가 그라디언트 힌트에 가려 표시되지 않음, guidanceShown이 화살표 상태만 기록해 힌트 표시 여부가 로그에 안 남음.

**핵심 진단: 문제는 화살표를 일찍 띄운 것이 아니라, 낮은 확신을 화살표 표시로 구별해 주지 않은 것. v2는 '숨김'으로 풀었으나 v3는 '정확도 표시'로 푼다.**

## 2. 요구사항 (사람 언어)

### R1. 화살표는 방향을 보장할 수 있으면 표시한다 (교차 리뷰 H1 반영)
- 관측 2개로 한 축만 성립해도, 목표가 그 축 밖이어도 **방향 화살표**를 띄운다.
- **축외 허용 컷은 스텝 수가 아니라 각도 불변량**: `asin(미지 축 불확실성 / 목표 거리) ≤ θmax(초기값 30°)`일 때만 화살표. 근거(260919 실측): 종료 시점 기기가 J4에서 3.5m인데 미지 번호축 피치 4.6~5.0m → 스텝 수 컷으로는 근접 시 방위 오차 최대 180°를 못 막음. **각도 보장이 무너지는 지점 = 근접 모드(카드·힌트) 자동 전환점**으로 통합 — 멀 때는 화살표가 유효하고 가까울 때는 카드가 유효하다는 자연 분업.
- 하드 차단은 물리 부조리(G2) 단 하나. **단 G2 상한 15m는 오설정으로 정정: 20m로** — 260919 실측 구역 피치 16.0~16.9m/스텝이 정상 격자인데 기각됨(ParkingTuning 주석 스스로 "실측 1.5~16.7m"라 적고 15로 설정한 자가당착). 이 정정 없이는 클러스터를 넣어도 260919 가동률 0% 유지.

### R2. 정확도를 %로, 항상 표시한다 (확정: % 표기)
- 레버·관측 수·신선도·잔차·인접 목격에서 **연속 점수(0~1)** 를 계산해 %로 표시. **상한 95% — 100%는 절대 표시하지 않음**(구조상 도달 불가, 과신 방지).
- 화살표 형태는 % 구간에 연동 (구간 경계 수치는 리플레이 캘리브레이션으로 확정):
  - **저구간** (예: <40%): 화살표 **반투명/점선** + 거리 숨김(방향만). 한 축만 성립·레버 초과·표시 거리 60m 초과가 여기 해당
  - **중구간**: 실선 화살표 + 거리 "약 Nm"
  - **고구간** (관측 5+·잔차 정상·인접 목격): 실선 + 거리, 게이지 초록
- 정밀해 보이는 거리 숫자로 과신 유발 금지 — 저구간 거리 숨김은 하드 규칙.
- **점수 설계의 명시적 한계와 방어 (H3)**: ① 정확결정계(관측 최소)에서는 잔차가 항등 0 — 잔차 성분을 만점이 아니라 **미정보 처리**(v2 residualInformative 게이팅 유지) ② 공분산 기반 점수는 연관 오류(드리프트·다중 표지판)를 못 잡는다는 v2의 보류 사유는 유효 — 그래서 %는 "하한 보장"이 아니라 "정직한 추정"이며, 관측 수 게이트(고구간 5+)와 각도 컷(R1)이 하한을 담당 ③ 화살표 표시의 바닥은 %가 아니라 R1의 각도 보장 — "항상 표시"의 유일한 예외로 명문화 (H4)
- **% 표시 히스테리시스**: 구간 경계에서 화살표 형태가 깜빡이지 않도록 전환 이력(±5%p) 적용.
- **G3 정정 (H4)**: 표시 거리 상한 60m 고정 상수는 오설정(260919 관측 이격 72.8m) — **관측 스팬 × 1.2의 상대 기준**으로 교체, 초과 시 방향만 모드(숨김 아님).

### R3. 관측할수록 정확도가 오르는 경험
- **다중 표지판 수용**: 4m+ 점프 코드를 영구 제외하지 않고 표지판 인스턴스별 위치 클러스터로 분리 수용(같은 코드의 복수 랜드마크). 격자에는 최근 목격 클러스터를 사용하되 **표본 2개 이상 클러스터만 채택**(유령 군집 방지 — 리뷰 실측: n=1 채택 시 잔차 0.18→2.27m 악화).
- **신선도 → 불확실성 팽창**: 30s 경과 관측을 제외하는 대신 가중치를 낮추고 % 점수에 반영. **팽창은 점수·표시에만 적용, 점추정(위치) 오염 금지.** 새 기둥을 비추면 회복 (v2 액션 6의 구현).
- **구현 범위 주의 (Sonnet H3)**: 클러스터·팽창·% 는 GridEstimator만이 아니라 **VM Observation·runEstimate·ParkingEventReplayer(VM 패리티 계약)·디버그 시각화 4곳 동시 개정**이다.

### R4. 행동 지시 병행
- needMore·낮음 정확도 상태에서 "무엇을 비추면 정확해지는지" 한 줄을 힌트와 **병행** 표시 (현행: 그라디언트 힌트가 축 지시를 가림 — 수정).
- 예: "같은 구역의 다른 번호 기둥을 비추면 정확도가 올라가요".

### R5. 계측 보강
- guidanceShown을 비화살표 상태(힌트 텍스트·정확도 등급 포함)에도 기록 — 다음 현장 분석이 추론에 의존하지 않게.
- 요약 스크립트에 정확도 등급별 가동률 추가.

### R6. UX 보조 (확정: 본 개발 범위 포함)
- **접이식 레이더 미니맵 — 포함**: 탑뷰에 내 위치·관측 기둥·목표 추정·불확실성 띠/원. 접힘 상태도 간단 라이브 버전 (§5 상세).
- **근접(~15m) 카드 — 포함**: 등록 기둥 사진 카드. **사진 없는 세션(수동 등록 등)은 목표 코드 대형 카드로 폴백** ("B2-A-3 기둥을 찾아보세요").
- 바닥 AR 경로(브레드크럼)는 **기각** — 통로 구조 미지 상태에서 벽 관통 경로·과신 유발.
- 햅틱/사운드는 Later.

### R7. 스캔 등록 품질 유도 (신규)
- 근거: 260919 스캔이 10초 만에 목표 1개만 담고 종료(인접 0) → find에서 고정확도 도달 불가. **스캔 품질이 find 정확도의 상한을 정한다.**
- 스캔 화면에 "주변 기둥 2~3개를 더 비추면 나중에 찾기 쉬워요" 유도 문구 + 확보한 인접 수 진행 표시(예: "인접 1/3").
- 강제 아님 — 저장은 현행대로 가능, 유도만. 인접 확보 수를 sessionStart에 이미 기록하므로 효과는 다음 현장 로그로 측정.

## 3. 검증 기준 (구현 전 리플레이 게이트, 교차 리뷰 반영판)

3열 비교의 실행 방법 정정(Sonnet H1 — "기존 규칙" 구현체는 코드에 없음): **① 로그에 기록된 당시 stage(=그 시점 규칙의 실측 결과) ② 현행 규칙 리플레이 ③ v3 규칙 리플레이** — 기존 규칙을 재구현하지 않고 기록치를 1열로 쓴다.

1. **가동률**: 260919 0% → 유의미 회복(저구간 % 포함 60%+ 목표), 260801·260911 세션도 v2 이전 수준 회복. 단 이 지표는 v3 구조상 자명하게 오르므로 **2·4와 반드시 묶어서만 통과 판정**
2. **사고 재발 방지**: J21(102m)·J22(30.3m) 세션에서 해당 구간의 표시 정확도가 저구간(%)에 머물 것 — 점선·거리 숨김 상태 (저% 표시는 허용, 그게 v3의 정직함)
3. **각도 오차 캘리브레이션**: θmax·미지 축 불확실성 추정의 검증은 **도착 성공 세션(260801 D5, 260911 H22)의 ground truth**로 수행 — 260919는 미도착이라 참값 없음
4. **자기불안정성**: targetEst 한 스텝 점프·누적 이동이 현행 대비 악화되지 않을 것
5. **리플레이어 패리티 비용 명시(Sonnet H2)**: 클러스터·팽창·% 를 리플레이어에 복제 + confidence 스키마는 **구 필드(Int 0/1/2) 유지 + 신 필드(conf%) 병행**으로 구 로그 하위 호환 + 픽스처 7건 재고정 — P2·P3 작업량에 포함
6. 게이트 통과 후 실기기 현장 검증 (다음 방문)

## 5. 화면 구성·미니맵 상세 (R6 구체화, 검토 반영)

### 화면 구역 (공통 골격)
- **바탕**: AR 카메라 전체 화면 (항상)
- **상단 1줄**: 상태 문구와 행동 지시가 같은 자리를 교대로 사용 — 텍스트는 최대 1~2줄 고정 (현행 힌트가 축 지시를 가리는 문제를 자리 통합으로 해결, R4)
- **중앙**: 화살표 + 정확도 게이지 + 거리 **한 덩어리** (방향 추정 있을 때만; 낮음이면 반투명/점선 + 거리 숨김)
- **인식 피드백**: 코드 확정 순간 해당 위치에 "J4 ✓" 칩 1~2초 반짝 — 목록으로 쌓지 않음. 칩 반짝임→게이지 상승의 인과가 보이는 것이 노림수
- **우하단**: 미니맵 (아래 상세)
- **하단**: 버튼 행 (수동입력·사진·조명 등, 현행 유지)
- 도착 근처(~15m): 화살표 묶음 → 등록 기둥 사진 카드로 전환
- 과부하 방지 원칙: 큰 요소는 한 번에 하나(화살표), 미니맵 펼침은 사용자 탭 시에만, 인식 피드백은 순간만

### 미니맵 — 접힘(기본): 간단 라이브 버전 (지름 ~64pt)
접힘 상태도 글리프 배지가 아니라 **라이브 축소판**. 요소 딱 3개, 라벨·눈금·자취 없음:
- 나 = 중심 점 + 작은 시야 쐐기 (heading-up — 화살표와 방위 항상 일치)
- 목표 = 색 블롭: 축 하나만 성립 시 **띠**, 격자 성립 시 **원**(레버 클수록 큼) — 관측할수록 띠→원→점으로 조여드는 "공간의 수렴"이 접힌 채로 보임 (게이지의 "수치 상승"과 역할 분담)
- 관측 기둥 = 옅은 점들
- 자동 축척(목표가 항상 원 안에), 목표가 매우 멀면 가장자리 클램프. 테두리 색 = 정확도 등급 색. 어떤 순간에도 0.5초 안에 읽히는 것이 기준

### 미니맵 — 펼침(탭): 상세 버전 (~화면 폭 45%)
