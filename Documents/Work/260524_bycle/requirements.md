## 1. 배경

현재 앱은 자동차 길찾기 중심의 네비게이션 앱이다.  
도시 모빌리티 기능을 단계적으로 확장하기 위해, **첫 번째 외부 데이터 통합으로 서울 공공자전거 "따릉이"** 기능을 추가한다.

향후 버스/지하철/주차 등의 도시 데이터도 동일한 패턴으로 통합할 계획이며, 이 기획은 그 첫 사례로서 **공통 인프라(레이어 토글, 외부 API 통합, 외부 앱 딥링크 패턴)** 를 함께 검증한다.

---

## 2. 목적

- 사용자가 **지도에서 주변 따릉이 정류소를 빠르게 확인**할 수 있게 한다
- 정류소의 **실시간 잔여 자전거 수**를 제공한다
- 따릉이로 이동하려는 사용자에게 **정류소까지 도보 길찾기**를 제공한다
- 대여는 **공식 앱으로 안전하게 위임**한다 (자체 결제/대여 미구현)

---

## 3. 범위

### In Scope
- 홈 화면 지도에 따릉이 정류소 표시 ON/OFF 토글
- 정류소 마커 (실시간 잔여 자전거 수 표시)
- 정류소 상세 시트 (따릉이 전용 디자인)
- 따릉이 공식 앱 실행 딥링크
- 따릉이 앱 미설치 시 App Store 자동 이동
- 정류소까지 도보 경로 안내 (기존 네비 활용)

### Out of Scope
- 자체 결제·회원·대여 처리 (불가능)
- 정류소별 자전거 종류 구분 (API 미제공)
- 자전거 전용 turn-by-turn 경로 (API 부재)
- 자치구·자전거 도로 데이터 (이번 단계 미반영)
- 버스/지하철/주차 기능 (별도 차후 단계)

## 4. 사용자 시나리오

### 시나리오 A — 주변 따릉이 찾기
1. 홈 화면에서 지도 우측 토글 버튼 `🚲 따릉이`를 탭
2. 지도 위에 주변 따릉이 정류소 마커가 표시됨 (잔여 자전거 수 배지)
3. 사용자가 원하는 정류소 마커를 탭
4. 화면 하단에 정류소 상세 시트가 올라옴
5. 정류소 정보(이름, 잔여 자전거, 거치대, 거리)를 확인

### 시나리오 B — 정류소까지 도보 이동
1. 시나리오 A 진행 후
2. 상세 시트의 `도보 길찾기` 버튼 탭
3. 기존 네비게이션 화면으로 전환 (도보 모드, 목적지 = 정류소 좌표)
4. 사용자가 정류소에 도착

### 시나리오 C — 자전거 대여
1. 시나리오 A 진행 후
2. 상세 시트의 `대여하기` 버튼 탭
3. 따릉이 공식 앱이 설치되어 있으면 → 따릉이 앱 실행
4. 미설치 시 → App Store 따릉이 페이지로 자동 이동

## 5. 기능 명세

### 5-1. 레이어 토글 버튼

| 항목 | 값 |
|---|---|
| 위치 | 지도 우측, 기존 `MapControlButtonsView` 스택 하단에 추가 |
| 표시 상태 | OFF (회색 아웃라인 아이콘) / ON (파란 채움 + 활성 표시) |
| 아이콘 | SF Symbol `bicycle` 또는 커스텀 |
| 동작 | 탭 → ON/OFF 토글 |

### 5-2. 정류소 마커

| 항목 | 값 |
|---|---|
| 표시 조건 | 토글 ON 시 지도에 보이는 영역만 (클라이언트 필터링) |
| 마커 형태 | 원형 배경 + 잔여 자전거 수 숫자 |
| 색상 코드 | 잔여 자전거 수에 따라 (5-3 참조) |
| 클러스터링 | MKAnnotationView 자동 클러스터링 (`clusteringIdentifier`) |
| 클러스터 표시 | 그룹 내 정류소 수, 잔여 자전거 합계 |

### 5-3. 색상 규칙 (잔여 자전거 수 기준)

| 상태 | 잔여 자전거 수 | 색상 |
|---|---|---|
| 여유 | 5대 이상 | 녹색 (`systemGreen`) |
| 부족 | 1~4대 | 주황 (`systemOrange`) |
| 대여 불가 | 0대 | 회색 (`systemGray`) |
| 반납 불가 | 거치대 만석 (`shared == 100`) | 회색 외곽 + 적색 보더 (필요 시) |

### 5-4. 정류소 상세 시트

따릉이 전용 디자인, 하단 시트 형태.

```
┌──────────────────────────────────┐
│  🚲                              │
│  102. 망원역 1번출구 앞          │
│                                  │
│  대여 가능        반납 가능        │
│   8 대            7 대           │  ← 큰 숫자, 색상
│  / 15            / 15            │
│                                  │
│  📍 현재 위치에서 320m            │
│  🕐 1분 전 갱신   [새로고침]     │
│                                  │
│  ┌────────────┬────────────┐    │
│  │  대여하기   │  도보 길찾기  │   │
│  └────────────┴────────────┘    │
└──────────────────────────────────┘
```

**필드 매핑**
- 정류소 이름: `stationName`
- 대여 가능: `parkingBikeTotCnt`
- 반납 가능: `rackTotCnt - parkingBikeTotCnt`
- 거치대 총: `rackTotCnt`
- 거리: 현재 위치 ↔ 정류소 좌표 (도보 추정)
- 갱신 시각: 마지막 API 호출 시각

### 5-5. 대여 (딥링크)

| 단계 | 동작 |
|---|---|
| 1 | iOS URL Scheme `ddareungi://` (또는 확인된 scheme) 으로 따릉이 앱 호출 시도 |
| 2 | `canOpenURL` 실패 시 → App Store URL `https://apps.apple.com/kr/app/id1037272004` 자동 이동 |
| 3 | 정류소 ID 전달은 불가 (앱 일반 실행만) |

> ⚠️ 따릉이 공식 URL Scheme이 미문서화 상태. 실제 IPA 확인 또는 fallback으로 항상 App Store로 보내는 것도 옵션.

### 5-6. 도보 길찾기

| 단계 | 동작 |
|---|---|
| 1 | `도보 길찾기` 버튼 탭 |
| 2 | 출발지 = 현재 위치, 도착지 = 정류소 좌표, 모드 = `.walking` |
| 3 | 기존 `RoutePreview` → `NavigationViewController` 흐름 재사용 |

### 5-7. 데이터 갱신 정책

**수동만 — 자동 폴링 없음.**

| 트리거 | 동작 |
|---|---|
| 따릉이 토글 OFF→ON | 전체 데이터 fetch |
| 상세 시트 새로고침 버튼 | 단건 fetch (`bikeList/1/1/{stationId}/`) |
| 앱 백그라운드 → 포그라운드 + 토글 ON | 전체 fetch |
| 그 외 | 캐시 사용 (TTL 없음, 명시적 갱신만) |

→ API 호출 최소화, 사용자가 명시적으로 갱신 의도 표현할 때만 호출

## 6. 데이터 / API

### 6-1. 사용 API

| API | 용도 | 호출 시점 |
|---|---|---|
| **OA-15493** `bikeList/{S}/{E}/` | 전체 정류소 + 실시간 잔여 | 토글 ON 시, 포그라운드 복귀 시 |
| **OA-15493** `bikeList/1/1/{stationId}/` | 개별 정류소 새로고침 | 상세 시트 새로고침 버튼 |

### 6-2. 호출 방식

**전체 호출**
- 4회 분할 호출 병렬: `(1,1000)`, `(1001,2000)`, `(2001,3000)`, `(3001,4000)`
- 최대 4,000건까지 수신 (현재 ~3,000개)
- 응답 합쳐서 메모리에 보관

**단건 호출**
- `bikeList/1/1/{stationId}/`
- 미문서화 패턴이지만 동작 확인됨
- 잘못된 ID는 `INFO-200` 반환 → 캐시 데이터 유지

### 6-3. 인증키
- 서울 열린데이터광장 일반 인증키 (자동 발급)
- 기본 한도 1,000회/일 (확장 신청 가능)
- 빌드 설정 또는 보안 저장소에서 주입 (소스 하드코딩 금지)

### 6-4. 캐시 전략

| 데이터 | 저장 위치 | 갱신 시점 |
|---|---|---|
| 전체 정류소 리스트 | `BikeStationCache` (싱글톤, 메모리) | 명시적 갱신만 |
| 마지막 갱신 시각 | 위와 함께 | fetch 완료 시 |

디스크 캐시 미사용 (앱 재실행 시 fresh fetch). 향후 필요 시 추가.

## 10. 완료 기준

### 기능
- 따릉이 토글로 정류소 ON/OFF 가능
- 정류소 마커가 잔여 자전거 수와 색상 코드를 정확히 표시
- 줌 레벨에 따라 자동 클러스터링 동작
- 정류소 탭 → 전용 상세 시트 표시
- 도보 길찾기 → 기존 네비게이션 도보 모드로 진입
- 대여 → 따릉이 앱 실행 또는 App Store 이동
- 새로고침 버튼으로 단건 갱신

### 비기능
- 4회 분할 호출이 모두 실패해도 앱 크래시 없음
- 토글 ON 직후 마커가 1초 이내 표시 (네트워크 정상)
- 다크모드에서 색상 가독성 유지
- API 호출은 명시적 트리거에서만 발생

### 검증
- 정류소가 ~3,000개 표시되어도 지도 성능 60fps 유지
- 잘못된 정류소 ID 호출 시 INFO-200 정상 처리
- 따릉이 앱 미설치 환경에서 App Store로 이동 확인

## 11. 향후 확장 포인트

이번 단계가 끝나면 동일 인프라로 다음 기능 추가 가능:
- **버스**: `getStationByPos` 좌표 기반 검색 (좌표 + 반경)
- **지하철**: 마스터 데이터 앱 번들 + 실시간 도착 API
- **주차장**: 정적 위치 표시 (실시간 잔여 없음)
- **레이어 다중 ON**: 토글 그룹 확장 (따릉이 + 지하철 동시 표시)
- **즐겨찾는 정류소**: 따릉이 정류소를 즐겨찾기 항목에 추가
